**Статус: черновик 1 (17 октября 2026).** Часть 1 — точки карты и реестр знамён, часть 2 — книга-гербовник.
Где Bynelog ещё не решил, выбрано решение по умолчанию и помечено **[по умолчанию]**. Числа, не проверенные в игре, помечены ⚠️.
Визуальный макет у Bynelog на холсте «Точки карты: концепт» (8 экранов); схемы ниже повторяют его.

## 1. Контекст: что есть сейчас

- `MapPoint` — точка, которую ставит администрация: имя, значок `icon` (`MapIcon`), краситель `dye` (для значка-знаменосца),
  граница (круг или многоугольник). Хранится в `MapPoints` (SavedData), рассылается всем `PointsSyncPayload`.
- Игрок открывает точку, когда заходит в её границу (`PointDiscovery`, вложение игрока).
- На карте (`MapScreen.renderPointIcons`) и на компасе (`CompassHud`) неоткрытая точка — белый «?» без названия
  (`PointShapes.drawUnknown`), открытая — свой значок. При наведении — ванильная подсказка: имя (только открытой или для
  администрации), «открыта / не открыта», координаты, расстояние.
- Окно точки у администрации — `WaypointEditScreen.point(...)`: имя, сетка значков, краситель, Сохранить / Удалить / Отмена.
- Боковая панель карандаша и стиля (`MapSidePanel`) стоит справа. Левая часть экрана карты свободна.

## 2. Что добавляем (кратко)

1. У неоткрытой точки под курсором подсвечивается значок и у курсора появляется окно с текстом от администрации.
2. Администрация выбирает два значка: до открытия («?» или любой) и после открытия.
3. Точка бывает «с описанием». Открытая точка с описанием кликается ЛКМ, слева открывается окно: знамя, название,
   описание с прокруткой, ниже блок сведений.
4. Знамёна — настоящие баннеры майнкрафта. Администрация вносит их в общий **реестр знамён** командой и дальше выбирает
   по id в точках и в книге, выдаёт себе в инвентарь.
5. Предмет **«Гербовник»** — книга знамён, которую администрация составляет из реестра.

> Слово «гербовник» дальше — только про книгу (часть 2). Список знамён администрации называется **реестр знамён**.

# Часть 1. Точки карты и реестр знамён

## Этап 1.1. Реестр знамён: данные, команды, синхронизация

**Данные** (новый пакет `banner`):
- `BannerEntry`: `id` (латиница, `[a-z0-9_]{1,32}`), `name` (≤ 32 символов), `description` (≤ 512 ⚠️, может быть пустым),
  `base` (`DyeColor` основы), `patterns` (`BannerPatternLayers` — ванильный тип слоёв узоров), `author` (ник, кто внёс).
- `BannerRegistry extends SavedData` (как `MapPoints`): `id → BannerEntry`, порядок — по времени внесения.
  Сохранение через кодек с `registries.createSerializationContext(NbtOps.INSTANCE)`: узоры баннеров — реестр данных,
  без контекста они не сохранятся.
- Узоры, которые мод добавит позже (`data/halgventmod/banner_pattern/...`), работают без доработок: в слоях хранятся
  ссылки на реестр узоров.

**Синхронизация:** `BannersSyncPayload` (сервер → все клиенты) со всем реестром — при входе и после каждой правки.
Кодек пакета — на `RegistryFriendlyByteBuf` (`BannerPatternLayers.STREAM_CODEC` требует его). На клиенте — карта `id → BannerEntry`.

**Команды** `/banner`, только администрация (`requires(source -> source.hasPermission(Permissions.ADMIN_LEVEL))`),
по образцу `LockCommand`; id подсказываются при вводе (`SuggestionProvider` по реестру):

| Команда | Что делает |
|---|---|
| `/banner register <id> <название>` | Вносит баннер из основной руки. Цвет основы — от предмета баннера, узоры — `DataComponents.BANNER_PATTERNS`. id занят — ошибка с подсказкой про `update`. |
| `/banner update <id>` | Заменяет цвет и узоры баннером из руки. Точки и книги покажут новое сами. |
| `/banner rename <id> <название>` | Новое название. |
| `/banner describe <id> <описание>` | Новое описание (видно в книге и в подсказках). |
| `/banner give <id> [игроки] [кол-во]` | Выдаёт копию баннера (по умолчанию себе, 1 шт.). |
| `/banner remove <id>` | Убирает знамя. Ссылки в точках и книгах не трогать: там просто станет пусто, а если знамя внесут снова под тем же id — вернётся. |
| `/banner list` | Открывает окно реестра (пакет клиенту). |

Сообщения — переводимые, с префиксом «[Реестр]»: внесено, обновлено, выдано, нет баннера в руке, нет такого id и т. п.

**Выданный баннер:** обычный ванильный баннер нужного цвета с узорами плюс компонент `halgventmod:registry_banner` (String id).
В подсказке (`ItemTooltipHandler`) золотая строка «Реестр знамён: <название>» — **только если** цвет и узоры стака совпадают
с записью реестра. Перекрасил на ткацком станке — строка пропадает сама (станок копирует компоненты, поэтому сверяем рисунок).

**Проверка:** внести баннер, выдать себе и второму игроку, переименовать, описать, обновить, удалить; перезапуск сервера —
реестр на месте; второй игрок видит строку в подсказке; после правки на ткацком станке строки нет.

## Этап 1.2. Знамя в интерфейсе и окно реестра

**Отрисовка.** Общий помощник `client/banner/BannerDraw.draw(graphics, entry, x, y, width)` — лицевая сторона флага
шириной `width` и высотой `2 × width` настоящими текстурами игры. Образец — `LoomScreen.renderBg`: деталь `flag` из
`ModelLayers.BANNER`, `BannerRenderer.renderPatterns(...)` с `ModelBakery.BANNER_BASE`, цветом основы и слоями.
Ширина — кратная 20 (флаг 20 × 40 текселей), чтобы пиксели были ровными. Нет записи в реестре — ничего не рисовать.

**Окно реестра** `BannerRegistryScreen` (только администрация, все действия проверяет сервер), стиль — как меню карты
(фон `0xF0241C14`, рамка `0xFF6E6250`, текст `0xFFE8DCC0`, заголовки `0xFFFFE8A0`):
```
┌ Реестр знамён ─────────────────────── [Поиск: ______] [×] ┐
│ подсказка: /banner register <id> <название>               │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐        │
│ │ ▓▓  Название │ │ ▓▓  Название │ │ ▓▓  Название │        │
│ │ ▓▓  id       │ │ ▓▓  id       │ │ ▓▓  id       │        │
│ │ ▓▓  В точках │ │ ...          │ │ ...          │        │
│ │ ▓▓ [Взять]   │ │              │ │              │        │
│ │    [Править] │ │              │ │              │        │
│ │    [Удалить] │ │              │ │              │        │
│ └──────────────┘ └──────────────┘ └──────────────┘        │
└───────────────────────────────────────────────────────────┘
```
- Карточки сеткой, прокрутка колёсиком; поиск по названию и id.
- «В точках: N» — считается на клиенте по `MapPoints.clientPoints` (поле `banner`, этап 1.3).
- «Взять» = `/banner give` себе (пакет серверу). «Править» — маленькое окно: название + описание (многострочное поле
  `MultiLineEditBox`). «Удалить» — с подтверждением.
- **Режим выбора:** то же окно, открытое из окна точки или из правки книги, — клик по карточке возвращает id вызвавшему
  окну и закрывается.

**Проверка:** окно открывается командой, знамёна выглядят как в игре (сравнить с баннером в руке), поиск, все три кнопки.

## Этап 1.3. Новые поля точки

В `MapPoint`:

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `hiddenIcon` | String | `""` | Значок до открытия: `""` — «?», иначе `MapIcon.id()`. |
| `hoverText` | String ≤ 256 ⚠️ | `""` | Текст в окне у курсора, пока точка не открыта. |
| `described` | boolean | `false` | Точка с описанием. |
| `banner` | String | `""` | id знамени из реестра, `""` — без знамени. |
| `description` | String ≤ 2000 ⚠️ | `""` | Описание под названием. |
| `info` | String ≤ 2000 ⚠️ | `""` | Нижний блок «Сведения». |

- Поле `icon` остаётся значком **после** открытия. Хочет администрация сразу показать город — ставит оба значка одинаковыми.
  `dye` остаётся цветом значка-знаменосца и к знамени отношения не имеет.
- Дописать в `copy`, сеть (`write`/`read`, длины строк ограничить), `save`/`load` (нет ключа — значение по умолчанию,
  старые миры грузятся), `valid()` (длины, `hiddenIcon` пустой или известный `MapIcon`).
- Все точки и так уходят всем игрокам целиком. С текстами пакет вырастет; если это станет заметно — описания можно будет
  отдавать по запросу, но не сейчас.

**Отрисовка значка неоткрытой точки** (`MapScreen.renderPointIcons` и `CompassHud`): `hiddenIcon` пустой — «?» как сейчас,
иначе этот значок. Название неоткрытой точки на компасе по-прежнему не показывать.

**Проверка:** старый мир с точками грузится; точка со значком деревни до открытия показывает деревню, после — свой значок.

## Этап 1.4. Наведение на неоткрытую точку

- Под курсором значок неоткрытой точки **подсвечивается**: мягкое свечение под значком (спрайт
  `textures/gui/map_point_glow.png`, 32 × 32, размер ≈ 1,6 значка, прозрачность ≈ 0,6 ⚠️) и «?» цветом заголовка `0xFFFFE8A0`.
- Вместо ванильной подсказки — **своё окно у курсора** в стиле меню карты: заголовок «Неизвестное место» (переводимый),
  ниже `hoverText` с переносом строк (ширина окна ≤ 200 единиц GUI ⚠️), ниже тусклым — координаты и расстояние.
  `hoverText` пустой — заголовок и координаты. Окно справа-снизу от курсора, у края экрана переворачивается внутрь.
- Администрация видит, как сейчас, имя и «не открыта», плюс `hoverText`, чтобы проверить текст.
- **[по умолчанию]** Открытая точка с описанием тоже подсвечивается под курсором, а в её подсказке последней строкой
  тусклое «ЛКМ — описание»: так видно, что она кликается.

**Проверка:** подсветка и окно у неоткрытой точки, переворот у краёв, длинный текст переносится.

## Этап 1.5. Окно описания открытой точки

Открытая точка с `described = true`: **ЛКМ** (нажали и отпустили, курсор сдвинулся не больше 3 px ⚠️ — иначе это
перетаскивание карты) открывает панель **внутри** `MapScreen` слева. Карта справа остаётся живой.
```
┌──────────────────────────────────────────────┐
│ ┌────────┐  Название точки             [×]   │
│ │        │  ─────────────────────────────    │
│ │ знамя  │  Описание, переносится по        ▐│
│ │ 3×     │  словам, прокрутка колёсиком,    ▐│
│ │ 60×120 │  ползунок, если не влезло        ▐│
│ │        │                                   │
│ └────────┘                                   │
│ ┌──────────────────────────────────────────┐ │
│ │ Сведения                                 │ │
│ │ Владелец: ...        (ключ до «:» тусклым)│ │
│ │ свободный текст администрации, тоже      │ │
│ │ с прокруткой                             │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```
- Ширина панели — `min(320, 45 % ширины)` ⚠️ единиц GUI, высота — вся, кроме полей. Не должна заходить под `MapSidePanel`;
  если на узком окне заходит — сообщи.
- Верхняя часть: слева место под знамя (`BannerDraw`, ширина 60 ⚠️); нет знамени или записи в реестре — место пустое.
  Справа название (крупнее, цвет заголовка), под ним описание. Нижняя часть до конца панели — «Сведения».
- Описание и сведения листаются колёсиком, когда курсор над ними; ползунок рисуется только если текст не влез.
- В сведениях строка вида «Слово: текст» рисует часть до двоеточия тусклым цветом.
- Закрыть: [×], Esc (первый Esc закрывает панель, второй — карту), клик по другой точке с описанием переключает панель.
- Точка без описания ведёт себя как сейчас.

**Проверка:** клик открывает, перетаскивание карты не открывает; длинные тексты листаются; знамя совпадает с баннером в игре;
удалили знамя из реестра — место пустое, окно не падает.

## Этап 1.6. Окно точки у администрации

Расширь окно точки (лучше вынести в отдельный `PointEditScreen`, а `WaypointEditScreen` оставить меткам игроков — на твоё
усмотрение). Две колонки:
```
 Название [__________]                │ [✓] С описанием
 Значок до открытия:  [?][замок][...] │ Знамя из реестра: Название (id)
 Значок после открытия: [замок][...]  │ [—][▓][▓][▓][▓][▓] [Весь реестр]
   (+ ряд красителей для знаменосца)  │ Описание
 Текст при наведении                  │ [многострочное поле        ]
 [многострочное поле           ]      │ Сведения
                                      │ [многострочное поле        ]
            [Сохранить] [Удалить] [Отмена]
```
- Многострочные поля — ванильный `MultiLineEditBox`, с ограничением длины как в 1.3.
- Ряд знамён — последние внесённые, «—» — без знамени, «Весь реестр» открывает реестр в режиме выбора.
- Галочка выключена — правая колонка неактивна, но значения не стираются.
- Окно должно помещаться в 1920 × 1080 при масштабе интерфейса 3 (≤ 640 × 360 единиц GUI). Не помещается — сообщи до вёрстки.

**Проверка:** все поля сохраняются и после перезапуска; второй игрок видит изменения сразу.

# Часть 2. Книга-гербовник

## Этап 2.1. Предмет и данные книги

- Предмет `armorial` — «Гербовник» / «Armorial», род М, `Category.MISC` **[по умолчанию]**, `stacksTo(1)`, свой класс
  `ArmorialItem`, описание: «Книга знамён. ПКМ — открыть.» Иконку нарисуем отдельно; до неё — заглушка.
- **Книг может быть несколько.** Компонент `halgventmod:armorial_book` (String, id книги). Нет компонента — книга `main`
  **[по умолчанию]**. В подсказке предмета — строка с названием книги.
- Содержимое книг — на сервере, `ArmorialBooks extends SavedData`: `id книги → Book { title, pages[] }`.
  `Page { type: LARGE | GRID, title (≤ 32), banners: List<String> }`: у LARGE один id (или `""`), у GRID ровно 9 (`""` — пустая ячейка).
  **Названия и описания знамён в книге не хранятся** — берутся из реестра, поэтому одно и то же знамя везде одинаковое.
- Команды `/armorial`, только администрация: `create <id> <название>`, `rename <id> <название>`, `give <id> [игроки]`,
  `remove <id>`, `list`.
- ПКМ книгой → сервер отправляет игроку `ArmorialContentPayload(id книги, Book, можно ли править)`, клиент открывает окно.
  Реестр знамён у клиента уже есть (этап 1.1).

## Этап 2.2. Окно книги

`ArmorialScreen` — раскрытая книга, **всегда две страницы**:
```
┌─────────────────────────────┬─────────────────────────────┐
│      Название страницы      │      Название страницы      │
│ ─────────────────────────── │ ─────────────────────────── │
│ ┌──────┐ Название знамени   │  ┌───┐  ┌───┐  ┌───┐        │
│ │      │ ────────────────── │  │ ▓ │  │ ▓ │  │ ▓ │        │
│ │знамя │ Описание знамени   │  └───┘  └───┘  └───┘        │
│ │ 3×   │ из реестра, с      │  ┌───┐  ┌───┐  ┌───┐        │
│ │      │ переносом строк    │  │ ▓ │  │ ▓◀┐│ │ ▓ │  сетка │
│ └──────┘                    │  └───┘  └───┘│ └───┘  3 × 3 │
│                             │   ┌──────────┴─────┐        │
│                             │   │ Название       │        │
│                             │   │ Описание       │        │
│ ◀            1              │   └────────────────┘    2  ▶│
└─────────────────────────────┴─────────────────────────────┘
```
- Текстура книги `textures/gui/armorial.png` — заглушка (пергамент, кожаная обложка, тень у корешка); финальную нарисуем.
  Размер окна ≈ 300 × 200 единиц GUI ⚠️, помещается в 640 × 360.
- Слева нечётная страница, справа чётная. Нечётное число страниц — правая последняя пустая и без номера.
- Листать: стрелки в нижних углах (как `PageButton` в ванильной `BookViewScreen`), колёсико, клавиши ← → и PageUp/PageDown.
  Звук `SoundEvents.BOOK_PAGE_TURN`. Листается по развороту (на две страницы).
- Сверху каждой страницы — её название по центру и черта под ним; снизу по центру — номер страницы.
- **LARGE:** слева большое знамя (`BannerDraw`, ширина 60 ⚠️), справа название знамени цветом заголовка, черта, описание
  с переносом. Не влезло — описание листается колёсиком, когда курсор над ним (в остальных местах колёсико листает книгу).
- **GRID:** сетка 3 × 3, знамёна поменьше (ширина 40 ⚠️). Пустые ячейки — бледная рамка. Наведение на знамя — ячейка
  подсвечивается, у курсора окно (стиль меню карты, как в 1.4) с названием и описанием. Пустая ячейка — без окна.
- Знамени нет в реестре — ячейка пустая.
- Книга без страниц — по центру «Книга пуста».
- **[по умолчанию]** Клиент до конца сеанса помнит открытый разворот каждой книги.

**Проверка:** листание во все стороны всеми способами, номера, оба типа страниц, окно у курсора, нечётное число страниц,
пустая книга, книга `main` без компонента.

## Этап 2.3. Правка книги администрацией

Администрация в творческом режиме открывает книгу сразу **в режиме правки** (тот же экран):
```
 Правка книги «...»                       [+ Страница в конец] [Готово]
┌──────────────────────────────┬───────────────────────────────┐
│ [Большое знамя][9 знамён] ‹›×│ [Большое знамя][9 знамён] ‹›× │
│ [ Название страницы        ] │ [ Название страницы         ] │
│ ┌ ─ ─ ┐ Название (из реестра)│  [▓×] [▓×] [▓×]               │
│   ▓▓    Описание (из реестра)│  [▓×] [▓×] [ + ]              │
│ └ ─ ─ ┘                      │  [ + ] [ + ] [ + ]            │
│ [Сменить знамя]              │                               │
│ [Править в реестре]          │                               │
└──────────────────────────────┴───────────────────────────────┘
```
- У каждой страницы: тип (LARGE / GRID; при смене первое знамя сохраняется), ‹ › — сдвинуть страницу, × — удалить
  (с подтверждением). Название — поле ввода.
- «Сменить знамя», «+» в ячейке — реестр в режиме выбора (этап 1.2). × в ячейке — очистить. «Править в реестре» — окно
  правки названия и описания этого знамени.
- «+ Страница в конец» добавляет пустую LARGE.
- **[по умолчанию]** Всё копится на клиенте и уходит одним `ArmorialEditPayload(id, Book)` по «Готово»; Esc с несохранёнными
  изменениями спрашивает «Сохранить?». Сервер проверяет права (`MapPoints.canEdit`), длины, число страниц (≤ 200 ⚠️),
  что id знамён пустые или есть в реестре, и сохраняет.
- Игроки, у которых книга открыта, увидят правку при следующем открытии.

**Проверка:** все действия правки; не-администратор не может отправить правку подделанным пакетом; после перезапуска всё на месте.

## Этап 2.4. Иконка и текстура

Заглушки из этапов 2.1–2.2 заменить, когда будут готовы рисунки (иконка предмета 32 × 32 в `textures/item/...`,
текстура книги). Пока — не трогать.

## Не делать

- Не менять ванильные баннеры, ткацкий станок и щиты; не добавлять новые узоры — это отдельная задача
  (реестр их поддержит сам).
- Не добавлять рецепт гербовника — его выдаёт администрация (см. открытые вопросы).
- Не трогать надписи, карандаш, метки игроков и границы точек (`PointBoundsEditor`), кроме мест, названных выше.
- Не рисовать финальную графику (свечение, книга, иконка) — только заглушки.
