# Кровь, анимации и голоса персонажа — техническое задание

Документ для реализации «телесных» эффектов игрока в моде **Halgventmod: Neoclassic**:

1. **Кровь** (разделы 3–6): брызги при ударе, следы крови на блоках при кровотечении.
2. **Анимации игрока** (разделы 7–9): бег, удары, блок, перевязка и т. д.
3. **Смерть** (разделы 10–11): анимация, в которой игроку отрубают руку и он падает.
4. **Голоса** (разделы 12–14): крик при уроне, набор голосов на выбор.

**Не входит**: труп после смерти (отдельное ТЗ позже), сама механика кровотечения, боли и поверженного состояния (это ТЗ боя по ГДД «Урон, защита и состояние персонажа» и таблице `TABLITsA1.xlsx`). Здесь только то, как это **выглядит и звучит**.

Разделы 15–17 — нагрузка, этапы, открытые вопросы.

## 0. Как работать с этим заданием

1. **Сначала изучи проект**: сеть (`ModNetwork`, payload-классы), вложения игрока (`ModAttachments`), рендер брони (`client/armor/ArmorLayer`, `ArmorRenderEvents`, `geo/`), миксины. Проверь, сделаны ли уже эффекты кровотечения и состояние «Повержен» из таблицы (id ниже); если нет — для проверки используй временную отладочную команду (раздел 5). Задание написано по устаревшей копии кода (0.0.2 с GitHub), сверь с текущим.
2. **Составь план по этапам** (раздел 16). Покажи план и дождись одобрения.
3. **Реализуй по одному этапу.** После каждого — сборка (`./gradlew build`), `runData`, проверка в игре.
4. **Решения, которые трудно отменить**, сначала обсуди с Bynelog: в первую очередь выбор библиотеки анимаций (раздел 7) — это новая зависимость мода.

**Не делать:**
- не менять механику урона, кровотечения, боли и поверженного состояния — только реагировать на неё;
- не ставить блоки в мир (кровь — не блоки, мир строят админы);
- не делать труп и выпадение вещей по-новому (отдельное ТЗ);
- не заменять полностью рендер игрока (например, через GeckoLib): это ломает слои брони мода.

**Соглашения проекта:** комментарии в коде на русском, короткие; числа — именованные константы, условные помечены ⚠️; переводы через `ModLanguageProvider`; CHANGELOG в два слоя.

## 2. Как это устроено в Майнкрафте (1.21.1)

- **Урон** считает сервер. После брони и всех правок срабатывает `LivingDamageEvent.Post` (в нём уже итоговый урон). Клиенты видят только «вспышку» красным и ванильный звук `entity.player.hurt`.
- **Частицы** создаются на клиенте. Сервер может прислать готовые частицы (`ServerLevel#sendParticles`), но для крови лучше один свой маленький пакет, а капли пусть считает каждый клиент сам (раздел 3).
- **Анимации игрока** в ванили процедурные: `HumanoidModel#setupAnim` качает руки и ноги синусом, удар — взмах одной рукой. Туловище не гнётся, локти и колени не сгибаются, ключевых кадров нет. Для настоящих анимаций нужна библиотека, которая подменяет повороты частей модели по ключевым кадрам из Blockbench (раздел 7).
- **Смерть** в ванили: модель за 1 с заваливается на бок и краснеет, потом облачко дыма, и игрок пропадает у остальных. Экран смерти у умершего — сразу.
- **Звук урона** игрока: `Player#getHurtSound`/`getDeathSound`, проигрывается сервером для всех рядом. В NeoForge есть событие `PlayLevelSoundEvent`, в котором звук можно подменить без миксина ⚠️.

# Часть 1. Кровь

## 3. Брызги при ударе

**Когда**: сервер, `LivingDamageEvent.Post`, если до тела дошёл урон > 0 (здоровье реально уменьшилось). Удар, который целиком погасила броня, крови не даёт (для него — искры/звон, это ТЗ боя).

**Кто кровоточит**: игроки всегда; мобы — по тегу сущностей `halgventmod:bleeds` (по умолчанию: животные и люди — корова, свинья, овца, лошадь, волк, кабан ⚠️, жители). Тег `halgventmod:no_blood` — скелеты и подобные, никогда.

**Пакет**: `BloodSplashPayload(entityId, точка удара, направление, сила, тип, seed)` — всем, кто видит пострадавшего (`PacketDistributor.sendToPlayersTrackingEntityAndSelf`). Капли каждый клиент строит сам из `seed`, поэтому у всех игроков **одинаковые** брызги и пятна.
- Точка удара: высота груди ⚠️; когда в бою появятся зоны попадания (голова, туловище, руки, ноги), — по зоне.
- Направление: от атакующего через жертву (кровь летит «за» удар); без атакующего (стрела — по её полёту, падение и огонь — крови нет).

## 4. Капли и сила

- Частица `blood_drop`: маленькая, тёмно-красная, падает с гравитацией. Коснулась твёрдой поверхности → на её месте пятно (раздел 6), капля исчезает. Упала в воду → растворяется тремя-четырьмя бледными частичками, пятна нет.
- Число капель ∝ урону: 3 при уроне 3, до 25 при 30+ ⚠️; разброс конусом вокруг направления.

| Тип урона (по ГДД) | Брызги |
|---|---|
| рубящий | широкий веер, много капель |
| режущий | узкая полоса вдоль удара, много капель |
| колющий, проникающий (стрелы) | короткая струйка в точке попадания, мало капель |
| дробящий | только при большом уроне (≥ 15 ⚠️), немного |
| огонь, падение, голод, яд и т. п. | нет |

Пока своих типов урона из ГДД в моде нет, тип определяется по оружию в руке атакующего (меч/топор — рубящий, стрела — проникающий, остальное — дробящий) ⚠️.

## 5. Кровотечение: след крови

- Сила кровотечения (0 — нет, 1 — `bleeding_light`, 2 — `bleeding_heavy` или `torn_wound`) — маленькое синхронизируемое значение на игроке, рассылается **всем, кто его видит**, только при изменении (ванильные эффекты других игроков клиенту не видны ⚠️).
- **Лёгкое**: раз в 2–4 с ⚠️ с тела падает капля под ноги → пятно. За идущим остаётся редкий пунктир.
- **Сильное**: капля раз в 0.5 с, плюс видна струйка капель из раны (частицы у груди). Если игрок стоит на месте, пятна в одном блоке сливаются в лужицу (отдельная текстура, больше размером).
- Поверженный (`downed`) с кровотечением оставляет след, пока ползёт, и лужу, пока лежит.
- После перевязки (`bandaged`) капли прекращаются сразу; уже оставленные пятна остаются до конца своего срока.
- Пока эффектов нет в моде: отладочная команда `/halgvent debug bleed <игрок> <0|1|2>` (только оператор), её потом убрать.

## 6. Пятна крови на блоках

- Пятно — **не блок**, а клиентская декаль: плоский квадрат на грани блока (пол, стена; потолок не нужен), чуть над поверхностью (0.01), случайный поворот, 3–4 варианта текстуры, размер по капле. Рисуется так же, как «лежащие» частицы из ТЗ атмосферы (раздел 20 там, змеи) — переиспользуй.
- Освещение — по свету в точке, в темноте пятно тёмное.
- Срок: 60 с ⚠️ (от сильного кровотечения и лужи — 120 с), последние 10 с плавно бледнеет. В дождь на открытом небе — вдвое быстрее.
- Лимит пятен на клиенте 256 ⚠️, при переполнении исчезают самые старые.
- Блок под пятном сломан или заменён — пятно исчезает.
- **Настройка «Частицы»**: на «Минимум» нет летящих капель, но **пятна и след остаются** (они дешёвые и по ним можно выследить раненого, это честно для всех игроков). Отключение крови целиком — открытый вопрос.

# Часть 2. Анимации

## 7. Насколько хорошо можно сделать и чем

Можно довести до уровня модов Better Combat и Emotecraft: полноценные анимации всем телом по ключевым кадрам, с наклоном корпуса, поворотом плеч, сгибом локтей и коленей. Делаются в Blockbench на шаблоне модели игрока. Ограничения — время аниматора и совместимость с бронёй мода.

**Библиотека** (выбрать и согласовать с Bynelog, это новая зависимость):
- **Player Animation Library** (форк playerAnimator, формат анимаций GeckoLib/Blockbench) ⚠️ проверь наличие версии под NeoForge 1.21.1;
- **playerAnimator** (KosmX), на нём работают Better Combat и Emotecraft ⚠️ проверь версию под NeoForge 1.21.1;
- своё — только если обе не подходят (дорого).

Обе подменяют повороты частей стандартной модели (`ModelPart`) перед отрисовкой, поэтому слои брони мода, которые привязаны к частям тела, должны двигаться вместе с ними ⚠️. **Проверить в первую очередь**: шлем с забралом, поля шапели, плащи, перчатки (`geo`-детали); как ведёт себя броня при сгибе локтя/колена (если библиотека сгибает конечности, а слой брони не сгибается — сгиб выключить).

## 8. Список анимаций

Разделены на два вида. **Движение** считается на каждом клиенте сам по скорости и состоянию игрока — пакетов нет. **Действия** запускает сервер одним пакетом всем, кто видит игрока.

| Анимация | Вид | Комментарий |
|---|---|---|
| Ходьба | движение | вместо ванильного маятника: лёгкий наклон корпуса, встречный мах рук |
| Бег | движение | сильный наклон вперёд, согнутые руки |
| Шаг крадучись (присед) | движение | |
| Ходьба с тяжёлой ношей | движение | при перегрузе по весу мода (Обуза/Скованность/Тяжесть) — тяжелее шаг |
| Прыжок, приземление | движение | |
| Удар: рубящий сверху, рубящий сбоку, укол | действие | по типу удара оружия; двуручное отдельно от одноручного |
| Блок щитом / оружием | действие (удержание) | |
| Натяжение лука, выстрел, перезарядка арбалета | действие | |
| Получение урона (вздрагивание) | действие | короткая, накладывается поверх движения |
| Еда, питьё | действие | |
| Перевязка себя (2 с) и другого (5 с) | действие (удержание) | из таблицы «Медицина» |
| Падение в «Повержен», ползание, лежание | действие + движение | когда это состояние появится |
| Добивание поверженного | действие | у добивающего и у жертвы |
| Смерть | действие | раздел 10 |

- От первого лица: удары, блок, лук, еда, перевязка — анимация рук от первого лица (у библиотек это отдельный режим ⚠️); ходьба и бег от первого лица не меняются (иначе укачивает).
- Анимации рисует Bynelog/аниматор в Blockbench; до этого — простые заглушки, чтобы проверить код.

## 9. Технически

- Анимации лежат в ресурсах мода (`assets/halgventmod/player_animations/`), подменяются ресурспаком.
- Слои: движение снизу, действие поверх (действие может занимать только руки, тогда ноги продолжают шаг).
- Пакет действия: `PlayerActionAnimPayload(entityId, id анимации, скорость)`, сервер шлёт только при начале и отмене действия.

# Часть 3. Смерть

## 10. Когда какая анимация (решение Bynelog)

По таблице `TABLITsA1` здоровье 0 — это ещё **не смерть, а «Повержен»**: игрок падает и лежит до 120 с, а умирает уже лёжа (таймер, добивание, «Сдаться смерти»). Поэтому Bynelog решил: рука отрубается **только при добивании и при смерти от рубящего/режущего удара**, в остальных случаях персонаж просто падает:

| Ситуация | Анимация |
|---|---|
| Падение в «Повержен» | падает на колени, потом на землю. **Без** отрубленной руки (его ещё могут перевязать и поднять) |
| **Добивание** поверженного рубящим/режущим оружием | отрубленная рука: короткий удар, рука отлетает, фонтан крови, тело обмякает |
| Мгновенная смерть от рубящего/режущего удара (второе падение за 10 минут), а **пока поверженного нет в моде — любая смерть от такого удара** | отрубленная рука, затем падение (полная версия, раздел 11) |
| Остальные смерти (стрела, дробящее, таймер поверженного, голод, падение, огонь) | падение без руки: колени → земля |
| Лава, пустота | ванильное поведение |

## 11. Анимация с отрубленной рукой

- Длина ~2.5 с ⚠️. Рука — та, что ближе к атакующему.
- С момента удара рука на модели игрока скрыта; вместо неё **отдельный клиентский объект «рука»**: часть модели игрока с его скином и слоями брони этой руки (рукав, наплечник, перчатка) ⚠️ — если слои брони на отдельной руке сделать сложно, обсудить упрощение. Рука отлетает по удару с простой физикой, падает на землю и лежит.
- Из плеча — струя крови (брызги из части 1, сильнее обычного), под телом — лужа.
- Тело: шатается, падает на колени, затем на бок или лицом вниз.
- **Ванильная смерть отключается** для игроков: нет покраснения, заваливания и облачка дыма. Тело остаётся видно другим игрокам до конца анимации и ещё 3 с ⚠️ (потом его заменит труп из будущего ТЗ). Нужен миксин на длительность смерти (`LivingEntity#tickDeath`, ванильные 20 тиков) и на поворот тела при смерти в рендере ⚠️.
- **Сам умерший**: экран смерти показывается с задержкой на длину анимации, камера на это время — от третьего лица ⚠️. Вещи выпадают как сейчас (это тема ТЗ трупа).
- После возрождения у игрока обе руки, анимация не влияет ни на что.

# Часть 4. Голоса

## 12. Крики при уроне

| Событие | Звук голоса |
|---|---|
| Урон по телу < 8 ⚠️ | `hurt_light` — короткий стон/вскрик |
| Урон ≥ 8, или началось сильное кровотечение | `hurt_heavy` — крик |
| Смерть, добивание | `death` |
| Тики кровотечения, голода, жажды | **без звука** (иначе игрок кричал бы каждую секунду) |

- Перерыв между криками одного игрока не меньше 0.8 с ⚠️.
- Звук слышат все рядом (16 блоков), ползунок «Игроки», высота тона ±5 % случайно.
- Ванильные `entity.player.hurt*` и `entity.player.death` для игроков заменяются звуком голоса. Через `PlayLevelSoundEvent` на сервере ⚠️; если подмена там невозможна — миксин на `Player#getHurtSound`/`getDeathSound`.
- По желанию, когда будут записи: `effort` (выдох при ударе), `downed` (стон поверженного), `bandage` (боль при хирургическом наборе), `drown`, `burn`. В наборе необязательны: нет звука — тишина.

## 13. Наборы голосов

- Набор — данные в ресурсах мода: `assets/halgventmod/voices/<id>.json` с названием набора и звуками по событиям; сами звуки — в `sounds.json` (`halgventmod:voice.<id>.hurt_light` и т. д.), у каждого события 2–4 варианта.
- Стартовый состав ⚠️: 4 мужских (низкий, средний, высокий, старый) и 3 женских. Записи ищет/записывает Bynelog (озвучка или свободные паки CC0); до этого — заглушки.
- Выбранный набор хранится во вложении игрока (сохраняется, рассылается всем, кто его видит). Сервер проигрывает звук по id набора (в 1.21 звук можно отправить по id без регистрации события ⚠️), поэтому новые наборы добавляются только ресурсами.
- Без выбора — набор по умолчанию (средний мужской ⚠️).

## 14. Выбор голоса

- Команда `/voice` открывает окно: список наборов, у каждого кнопка «Прослушать» (проигрывает `hurt_heavy` только себе) и «Выбрать».
- Менять можно в любой момент ⚠️ (см. открытые вопросы). Позже окно можно встроить в создание персонажа.
- Админ: `/voice set <игрок> <набор>`.

## 15. Требования к нагрузке

- Сервер: на каждый удар один маленький пакет брызг; на каждое изменение силы кровотечения — один пакет; на каждое действие — один пакет анимации. Во время ходьбы и бега пакетов нет.
- Клиент: капли и пятна с жёсткими лимитами (раздел 6), без аллокаций в рендере пятен; пятна рисуются одним проходом.
- Анимации движения — без пакетов, считаются у каждого клиента.
- Проверка: стычка 10 на 10 с кровотечением у половины — нет просадки TPS, на клиенте FPS падает не больше 5 % ⚠️.

## 16. Этапы

1. Брызги при ударе и пятна на блоках (проверка на ванильном уроне и мобах).
2. След при кровотечении (через отладочную команду, пока нет эффектов).
3. Голоса: вложение, наборы, окно `/voice`, подмена криков и звука смерти.
4. **Согласовать библиотеку анимаций с Bynelog**, подключить, проверить броню мода на анимированной модели.
5. Анимации движения, затем действий (по мере готовности файлов от аниматора).
6. Смерть: отключение ванильной, падение, вариант с отрубленной рукой.
7. Анимации поверженного и добивания — когда в моде появится состояние «Повержен».
