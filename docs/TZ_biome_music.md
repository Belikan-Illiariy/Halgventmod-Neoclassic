# Музыка биомов и звуки мест: техническое задание

Документ для реализации своей музыкальной системы в моде **Halgventmod: Neoclassic**: ванильная музыка Майнкрафта отключается, каждому биому можно назначить свой трек или набор треков, которые играют по порядку, а в главном меню играет своя музыка мода (часть 1, разделы 0–10). Вторая часть (разделы 11–19) — невидимый блок-источник, который проигрывает звуки места в радиусе вокруг себя (рынок, кузница, пристань, таверна с бардом). Раздел 20 — требования к нагрузке для обеих частей.

---

## 0. Как работать с этим заданием

1. **Сначала изучи проект**: клиентские события (`client/`), сеть (`ModNetwork`, payload-классы), миксины (`halgventmod.mixins.json`), датаген. Своих биомов в моде пока нет, проверять их не нужно: система должна работать с любым id биома (будущие биомы мода, Conquest Reforged, ванильные), а для проверки бери ванильные биомы. Задание написано по устаревшей копии кода (0.0.2 с GitHub), поэтому то, что касается текущего устройства мода (сеть, миксины), сверь.
2. **Составь план по этапам** (разделы 9 и 18; части можно делать по очереди, сначала музыку): какие классы появятся, какие файлы изменятся. Покажи план и дождись одобрения.
3. **Реализуй по одному этапу.** После каждого — сборка (`./gradlew build`), `runData`, проверка в игре.
4. **Требования к нагрузке** — раздел 20, они обязательны для обеих частей.
5. **Решения, которые трудно отменить** (новые зависимости, формат файлов наборов, если он будет отличаться от раздела 4) сначала обсуди.

**Не делать:**
- не трогать ванильные звуки, кроме музыки: шаги, мобы, окружение (ambient), пластинки в проигрывателе остаются как есть;
- не делать свою громкость или отдельные настройки звука: используется ванильный ползунок «Музыка»;
- не добавлять музыку для пещер, воды, боя и т. п. (только биомы, см. открытые вопросы).

**Соглашения проекта:**
- комментарии в коде — на русском, короткие и понятные;
- переводы (тексты команд, подсказки) — только через `ModLanguageProvider` (датаген);
- все настраиваемые числа (длительность затухания, пауза, задержка на границе биома) — именованные константы в начале класса;
- ⚠️ отмечены места, которые я не проверил в исходниках NeoForge/Minecraft: проверь перед тем как опираться.
- CHANGELOG — в двух слоях, как обычно.

# Часть 1. Музыка

## 1. Контекст

- NeoForge **1.21.1**, Java **21**. Пакет `com.nrdhvnstd.halgventmod`, modid `halgventmod`.
- Мод поверх **Conquest Reforged**, игроки в режиме приключения, мир строят админы. Значит, музыку настраивают админы на сервере, а игрок просто слушает.
- Музыка играется **только на клиенте**. Сервер лишь хранит и рассылает настройки (какие биомы → какие треки).

---

## 2. Принятые решения (Bynelog может поменять)

Эти решения взяты по умолчанию, в запросе они не уточнялись. Их надо сделать константами или полями набора, чтобы их можно было легко поменять.

| # | Решение | Как сделано по умолчанию |
|---|---|---|
| Р1 | Ванильная музыка | Выключена **полностью**: в мире, в главном меню, в титрах, под водой, в креативе, в Незере и Энде. |
| Р1а | Главное меню | **Не тишина** (так решил Bynelog): играет свой набор меню из ресурсов мода (раздел 4.1), по порядку и по кругу, как наборы биомов. |
| Р2 | Биом без назначенной музыки | Тишина. |
| Р3 | Конец набора | После последнего трека набор начинается с первого (по кругу). |
| Р4 | Порядок | Строго по порядку из файла. Перемешивание не делаем; если понадобится, добавим поле `shuffle`. |
| Р5 | Пауза между треками | 5 секунд ⚠️ (число условное), задаётся в наборе полем `pause_seconds`. |
| Р6 | Смена биома | Текущий трек плавно затухает (3 с ⚠️), затем начинается набор нового биома с его первого трека. |
| Р7 | Граница биомов | Смена засчитывается, только если игрок пробыл в новом биоме 4 с ⚠️, чтобы музыка не дёргалась при ходьбе по границе. |
| Р8 | Возврат в биом | Набор начинается заново с первого трека (номер трека не запоминается). |
| Р9 | Общий набор у нескольких биомов | Переход между такими биомами музыку **не прерывает**. |

## 3. Отключение ванильной музыки

Вся ванильная фоновая музыка идёт через клиентский `MusicManager` (`Minecraft.getInstance().getMusicManager()`), который каждый тик спрашивает `Minecraft#getSituationalMusic()` (меню, титры, вода, креатив, `Biome#getBackgroundMusic`).

Способ (выбери один, предпочтительно первый):
1. ⚠️ Событие NeoForge `SelectMusicEvent` (клиентское, если оно есть в 21.1.x): всегда ставить музыку `null`. Без миксина.
2. Если события нет: клиентский миксин на `MusicManager#tick` с отменой (`@Inject(at = HEAD, cancellable = true)`), плюс `MusicManager#stopPlaying()` при входе в мир и в меню на случай, если ванильный трек уже начался.

Требования:
- после отключения в игре нет ни одного ванильного трека, включая главное меню и экран загрузки мира (в меню вместо ванильного играет набор меню мода, раздел 4.1);
- пластинки (`SoundSource.RECORDS`) продолжают работать;
- своя система (раздел 5) **не** использует `MusicManager`, иначе ванильная логика будет её перебивать.

## 4. Формат наборов (данные)

Наборы — **данные датапака на сервере**, чтобы админ мог менять их без пересборки мода и применять командой `/reload`.

Путь: `data/<namespace>/halgvent_music/<имя_набора>.json`. Регистрация через `AddReloadListenerEvent` (свой `SimpleJsonResourceReloadListener`) или datapack registry — на твой выбор, объясни в плане.

```json
{
  "biomes": [
    "halgventmod:grenngarn_forest",
    "#halgventmod:northern_coast"
  ],
  "tracks": [
    "halgventmod:music.forest_1",
    "halgventmod:music.forest_2",
    "halgventmod:music.forest_3"
  ],
  "pause_seconds": 5,
  "priority": 0
}
```

| Поле | Обязательное | Смысл |
|---|---|---|
| `biomes` | да | id биомов и/или теги биомов (`#`). Любой namespace: свой, Conquest Reforged, ванильный. |
| `tracks` | да | Список звуковых событий по порядку. Один трек — просто список из одного элемента. |
| `pause_seconds` | нет | Пауза между треками, по умолчанию константа из Р5. |
| `priority` | нет | Если биом попал в несколько наборов: побеждает больший `priority`; при равенстве — набор, где биом указан прямым id, а не тегом; дальше — первый по имени файла, с предупреждением в лог. |

Ошибки (неизвестный биом, неизвестный трек, пустой список) — предупреждение в лог с именем файла, набор пропускается или трек выкидывается, игра не падает.

id биомов в примере условные: своих биомов в моде пока нет, их добавят позже. Для тестового набора используй ванильные биомы (`minecraft:forest`, `minecraft:plains`, тег `#minecraft:is_ocean`).

### 4.1. Набор главного меню

В главном меню сервера ещё нет, поэтому набор меню лежит **в ресурсах мода (клиент)**, а не в датапаке:

`assets/halgventmod/halgvent_music/menu.json` — тот же формат, но без `biomes` и `priority`:

```json
{
  "tracks": ["halgventmod:music.menu_1", "halgventmod:music.menu_2"],
  "pause_seconds": 5
}
```

- загрузка через клиентский reload listener (`RegisterClientReloadListenersEvent`), чтобы набор можно было заменить ресурспаком;
- играет на всех экранах вне мира: главное меню, выбор мира/сервера, настройки, экран загрузки и подключения;
- если файла нет или он пустой, в меню тишина и предупреждение в лог.

## 5. Проигрывание (клиент)

Новый клиентский класс-контроллер (например `client/music/BiomeMusicPlayer`), тикается в `ClientTickEvent.Post`.

Каждый тик (биом под игроком можно проверять реже, см. раздел 20):
1. Если нет мира или игрока (меню и другие экраны вне мира) — играет набор меню (раздел 4.1).
2. Биом под игроком: `level.getBiome(player.blockPosition())`. По нему ищется набор (правила из раздела 4).
3. Логика смены набора — по Р6, Р7, Р9. Сравнивать **наборы**, а не биомы.
4. Если трек закончился (`SoundManager#isActive(instance) == false`) — выждать паузу и включить следующий; после последнего — первый (Р3).
5. Громкость музыки биома умножается на множитель приглушения от источников звука из части 2 (раздел 16, поле `mute_music`). Поэтому трек играть своим `AbstractTickableSoundInstance` с изменяемой громкостью.

Как играть трек:
- `SimpleSoundInstance` с `SoundSource.MUSIC` (работает ванильный ползунок «Музыка»), без зацикливания, `relative = true`, `Attenuation.NONE`;
- для плавного затухания понадобится свой `AbstractTickableSoundInstance` с изменяемой громкостью;
- `SoundEvent` для трека можно не регистрировать: на клиенте достаточно `SoundEvent.createVariableRangeEvent(id)` и записи в `sounds.json` ⚠️.

Прочее:
- вход в мир: музыка меню затухает (как в Р6), дальше набор биома; выход в меню: музыка биома затухает, набор меню начинается с первого трека;
- смена измерения, смерть с экраном возрождения — корректно: после возрождения продолжить по биому, экран смерти музыку меню не включает;
- `/reload` или новые данные с сервера — пересчитать набор; если текущий трек есть в новом наборе, не прерывать.

---

## 6. Синхронизация

- Сервер отправляет клиенту таблицу «набор → биомы, треки, пауза, приоритет» при входе игрока и после `/reload` (`OnDatapackSyncEvent`).
- Новый payload в `ModNetwork` (по образцу `CalendarSyncPayload`).
- Клиент хранит только полученную таблицу; своих файлов наборов у клиента нет.

---

## 7. Ресурсы (сами треки)

- Файлы: `assets/halgventmod/sounds/music/<имя>.ogg` (Ogg Vorbis; моно или стерео — без разницы, т. к. звук не позиционный).
- `assets/halgventmod/sounds.json`: каждая запись с `"stream": true` (иначе длинные треки грузятся целиком в память).

```json
{
  "music.forest_1": {
    "category": "music",
    "sounds": [{ "name": "halgventmod:music/forest_1", "stream": true }]
  }
}
```

- Для проверки положи 2–3 коротких тестовых трека (можно тишину/тон по 10–20 с), тестовый набор на два-три ванильных биома и тестовый набор меню; перед релизом тестовые файлы убрать или заменить на реальные.

---

## 8. Команды для админа

Минимум, чтобы настраивать музыку было удобно:
- `/halgventmusic info` (клиентская команда, `RegisterClientCommandsEvent`) — пишет в чат: id биома под игроком, его теги, какой набор выбран, какой трек и какой по счёту играет;
- `/halgventmusic skip` — следующий трек набора (только для себя, на клиенте).

Больше команд не нужно; наборы правятся файлами + `/reload`.

---

## 9. Этапы

1. **Отключить ванильную музыку** (раздел 3). Проверка: в меню, мире, под водой, в креативе, в Незере нет ванильных треков; пластинка в проигрывателе играет.
2. **Формат данных и загрузка** (раздел 4) + синхронизация (раздел 6). Проверка: `/halgventmusic info` показывает правильный набор; ошибка в файле — предупреждение, без падения.
3. **Проигрыватель** (раздел 5) + набор меню (раздел 4.1) + тестовые треки (раздел 7). Проверка: в главном меню играет набор меню; треки идут по порядку, после последнего — первый; пауза соблюдается; ползунок «Музыка» работает.
4. **Переходы**: затухание, задержка на границе, общий набор у двух биомов не прерывается, меню ↔ мир, `/reload` на лету.

## 10. Открытые вопросы (часть 1)

1. Нужна ли особая музыка для **пещер/подземелий, воды, ночи, боя**? Сейчас — только по биому.
2. Должна ли музыка **зависеть от времени суток или календаря мода** (`WorldCalendar`), например дневной и ночной набор у одного биома? Формат легко расширить полем `time`, но сейчас не делаем.
3. Перемешивание треков (Р4) и запоминание места в наборе при возврате (Р8) — нужно ли?
4. Должен ли игрок иметь возможность выключить только музыку биомов, не трогая остальное? Сейчас за это отвечает ванильный ползунок «Музыка».

# Часть 2. Источник звука (звуки мест)

## 11. Что нужно

Админ ставит посреди площади **невидимый блок**. Пока игрок в радиусе (например, 20 блоков), он слышит звуки места: непрерывный гул рынка и, раз в 5 секунд, стук копыт. Вышел из радиуса — звук плавно стих.

В моде уже есть пустой `ModBlocks` (с комментарием «Здесь будут блоки»), это будет первый блок.

---

## 12. Принятые решения (Bynelog может поменять)

| # | Решение | Как сделано по умолчанию |
|---|---|---|
| З1 | Где настройки звука | **Сцены** в датапаке (раздел 14): «рынок», «кузница» и т. п. Блок хранит только id сцены и, если надо, свой радиус. Так один и тот же рынок в десяти городах правится в одном файле. |
| З2 | Громкость по расстоянию | До `full_radius` (по умолчанию половина радиуса) — полная громкость, дальше плавно до нуля к краю радиуса, за радиусом не слышно. |
| З3 | Откуда слышно | Непрерывный слой (гул рынка) звучит **вокруг игрока**, без направления: внутри площади шум окружает. Разовые звуки (копыта) — **из случайной точки** в пределах `offset` блоков от источника, с направлением: слышно, с какой стороны проехала телега. |
| З4 | Интервал | Ровно `interval_seconds`; поле `interval_spread` (± секунд) по умолчанию 0. |
| З5 | Варианты разового звука | Если у слоя несколько файлов, каждый раз берётся случайный, но не тот же, что в прошлый раз. |
| З6 | Ползунок громкости | Ванильный «Окружение» (`SoundSource.AMBIENT`). |
| З7 | Музыка биома | Если в сцене `mute_music: true`, музыка биома **плавно стихает по мере приближения к блоку** (так решил Bynelog): на краю радиуса полная громкость, у самого блока ноль. Если нет — играет вместе со звуками места. Свою музыку места (бард в таверне) даёт слой `playlist`. |
| З8 | Два источника с одной сценой рядом | Слышен только ближайший, чтобы гул не удваивался. Разные сцены звучат вместе. |
| З9 | Видимость | Игроки блок не видят, сквозь него ходят и не могут его кликнуть или сломать. Админ в творческом режиме с предметом этого блока в руке видит значок (как ванильный блок света) и может настроить или сломать блок. |

---

## 13. Блок

- Блок `sound_emitter` в `ModBlocks` + `BlockEntity` + предмет блока (в творческой вкладке для админов; как регистрировать предмет блока при билдере `item(...)` в `ModItems` — предложи в плане).
- Свойства как у ванильного блока света/барьера: `RenderShape.INVISIBLE`, без коллизии и затенения, не пропускает действия игроков в приключении, прочность −1 (ломается только в творческом), без дропа.
- Форма: пустая, **кроме** случая, когда игрок держит предмет этого блока (`CollisionContext#isHoldingItem`, как в `LightBlock`). Тогда его можно навести, кликнуть и сломать.
- Значок для админа: частица `minecraft:block_marker` с текстурой блока над источниками рядом, пока предмет в руке ⚠️ (у ванильного света это зашито под свои предметы, скорее всего понадобится свой клиентский тик).
- `BlockEntity` хранит: `scene` (id сцены), `radius` (необязательно, иначе из сцены). **Серверного тикера нет** (раздел 20). Синхронизация клиенту через `getUpdatePacket`/`getUpdateTag`.

---

## 14. Формат сцены (данные)

Путь: `data/<namespace>/halgvent_sound_scene/<имя>.json`, загрузка и синхронизация клиенту так же, как наборы музыки (разделы 4 и 6), применяется через `/reload`.

```json
{
  "radius": 20,
  "full_radius": 10,
  "mute_music": false,
  "layers": [
    {
      "type": "loop",
      "sound": "halgventmod:ambient.market_crowd",
      "volume": 1.0
    },
    {
      "type": "interval",
      "sounds": ["halgventmod:ambient.hooves_1", "halgventmod:ambient.hooves_2"],
      "interval_seconds": 5,
      "interval_spread": 0,
      "offset": 8,
      "volume": 0.8
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `radius` | Радиус слышимости, блоки. Блок может переопределить. |
| `full_radius` | До какого расстояния громкость полная (З2). По умолчанию `radius / 2`. |
| `mute_music` | Глушить ли музыку биома рядом с блоком (З7). По умолчанию `false`. |
| `layers` | Слои, играют одновременно. Сколько угодно. |
| `type: loop` | Непрерывный звук по кругу, без паузы, без направления (З3). |
| `type: interval` | Разовый звук раз в `interval_seconds` (± `interval_spread`), из случайной точки в пределах `offset` блоков (0 = из самого блока). |
| `type: playlist` | Своя музыка места: `sounds` — треки по порядку и по кругу, `pause_seconds` между ними, без направления, ползунок «Музыка». Громкость от расстояния как у `loop`. |
| `volume` | Громкость слоя 0–1, умножается на громкость от расстояния. |

Ошибки в файле — предупреждение в лог, слой или сцена пропускаются, игра не падает. Блок с несуществующей сценой молчит, а админ с предметом в руке видит это в окне настройки.

---

## 15. Настройка блока админом

- ПКМ по блоку с его предметом в руке (только творческий режим и права оператора ⚠️ уровень 2) — небольшое окно:
  - список сцен (из синхронизированных с сервера), выбрать одну;
  - поле «Радиус» (пусто = из сцены, 1–64 ⚠️);
  - кнопка «Готово».
- Окно шлёт payload на сервер; сервер проверяет права и расстояние, записывает в `BlockEntity`, рассылает обновление.
- Подсказка предмета блока (через `ItemTooltipHandler`/переводы): «Невидимый источник звука. ПКМ — настроить».

---

## 16. Проигрывание (клиент)

- Клиентский тикер `BlockEntity` (или общий менеджер, которому источники сообщают о себе при загрузке/выгрузке чанка) раз в несколько тиков считает расстояние до игрока.
- Для каждой сцены выбирается ближайший источник в радиусе (З8).
- **loop**: свой `AbstractTickableSoundInstance` с `looping = true`, `relative = true`, `Attenuation.NONE`; громкость каждый тик = `volume ×` громкость от расстояния (З2); вход и выход из радиуса — затухание ~1 с ⚠️. Звук не перезапускается, пока игрок в радиусе.
- **interval**: свой таймер у слоя; первый звук через интервал после входа в радиус. Звук — обычный `SimpleSoundInstance` в мировой точке (`источник + случайный сдвиг до offset`), `Attenuation.LINEAR`, с радиусом слышимости не меньше `radius` (например, `SoundEvent.createFixedRangeEvent`) ⚠️.
- **playlist**: как loop по громкости, но треки по порядку с паузой (логика как в разделе 5), `SoundSource.MUSIC`. Игрок вышел из радиуса — трек затухает; вернулся — набор начинается с первого трека.
- **mute_music**: множитель музыки биома = `расстояние / radius` (0 у блока, 1 на краю и дальше). Если рядом несколько таких источников, берётся наименьший множитель. Передаётся в проигрыватель части 1 (раздел 5, п. 5). Музыка биома при этом не останавливается, а только тише, поэтому когда игрок уходит, она плавно возвращается с того же места.
- Выгрузка чанка, выход из мира, смена измерения, сломанный блок — все звуки этого источника останавливаются, приглушение музыки снимается.
- Сквозь стены звук не глушится (в ванили такого нет), см. открытые вопросы.

---

## 17. Ресурсы

- Файлы в `assets/halgventmod/sounds/ambient/`, записи в `sounds.json` с `"category": "ambient"`; короткий гул и разовые звуки без `stream`, `stream` только для длинных файлов (раздел 20).
- **Разовые звуки с направлением — только моно.** Стерео-файлы в Майнкрафте не позиционируются и звучат «в голове» отовсюду.
- Непрерывный гул нарезать так, чтобы конец бесшовно переходил в начало, иначе на стыке будет щелчок.
- Для проверки: тестовая сцена `market` с коротким шумом и двумя «стуками», тестовые файлы перед релизом убрать или заменить.

## 18. Этапы

1. **Блок**: регистрация, невидимость, значок и клик только с предметом в руке, `BlockEntity` с синхронизацией. Проверка: игрок в приключении блок не видит и не задевает; админ с предметом видит значок и ломает блок.
2. **Сцены**: формат (раздел 14), загрузка, синхронизация, `/reload`.
3. **Окно настройки** (раздел 15) и проверка прав.
4. **Проигрывание** (раздел 16): loop и interval, громкость по расстоянию, ползунок «Окружение». Проверка на тестовой сцене рынка: гул слышен в радиусе 20, стук копыт раз в 5 с с разных сторон.
5. **Музыка места**: слой `playlist` и `mute_music`. Проверка на тестовой «таверне»: при подходе музыка биома стихает, музыка барда нарастает; при уходе наоборот.
6. **Края и нагрузка**: два источника одной сцены рядом, разные сцены рядом, выгрузка чанка, сломанный блок, вход в радиус и выход; 50 источников рядом без просадки (раздел 20).

## 19. Открытые вопросы (часть 2)

1. Должны ли звуки места **зависеть от времени суток** (`WorldCalendar`): рынок шумит днём, ночью тихо?
2. Нужно ли **глушить звук стенами** (вошёл в дом с площади — гул тише)? В ванили этого нет, придётся считать самим.
3. Показывать ли админу **границу радиуса** (кольцо частиц), пока он держит предмет?

# Нагрузка

## 20. Требования к нагрузке (обе части)

Идея: **на сервере во время игры не происходит ничего**, вся работа со звуком идёт на клиенте и только рядом с игроком.

**Сервер**
- Часть 1: ничего не тикает. Работа только при `/reload` и входе игрока: разобрать JSON и отправить один пакет с таблицей наборов и сцен (единицы КБ).
- Часть 2: у `BlockEntity` источника **нет серверного тикера** (`getTicker` на сервере возвращает `null`). Его данные (id сцены и радиус) уходят клиенту вместе с чанком и ещё раз, только когда админ их меняет. Во время игры пакетов нет вообще.
- Следствие, которое надо принять: таймеры у каждого клиента свои, поэтому два игрока услышат копыта в разные моменты. Для фоновых звуков это незаметно, а сеть не нагружается.

**Клиент**
- Биом под игроком проверять раз в 10 тиков ⚠️, не каждый тик: задержка на границе (Р7) всё равно 4 с.
- Источники: **не** тикер у каждого `BlockEntity` и **не** перебор блоков в мире, а один клиентский менеджер со списком источников. Источник добавляется в список при загрузке на клиенте (`onLoad`) и убирается при `setRemoved`/выгрузке чанка.
- Менеджер раз в 5 тиков ⚠️ сравнивает квадраты расстояний до игрока (без `sqrt` для дальних); сотни источников — это доли миллисекунды. Каждый тик плавно меняется громкость только у звучащих звуков.
- Звук не пересоздаётся, пока игрок в радиусе: один инстанс на слой сцены.
- **Лимит каналов.** У звукового движка Майнкрафта мало каналов для потоковых (`"stream": true`) звуков, около 8 ⚠️ (проверь в `SoundEngine`/`ChannelAccess`). Один занимает музыка. Поэтому:
  - одновременно звучат не больше N ближайших сцен (константа, 4 ⚠️), остальные молчат, пока не станут ближе;
  - короткий непрерывный гул (до ~30 с ⚠️) и все разовые звуки — **без** `stream`: грузятся в память один раз и не занимают потоковые каналы;
  - `stream` — только для длинных треков (музыка биомов, меню, `playlist`).
- Значок источника для админа рисуется только пока предмет в руке; у обычных игроков источник ничего не рендерит.
- Ogg-файлы держать разумного размера (моно для разовых звуков, качество Vorbis ~q4–5 ⚠️ достаточно).

**Проверка нагрузки** (этап 6 части 2): 50 источников разных сцен в радиусе прорисовки, в F3 нет просадки FPS и TPS сервера, в логе нет предупреждений о нехватке каналов (`Failed to create new sound handle` ⚠️).
