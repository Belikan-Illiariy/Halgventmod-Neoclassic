## 1. Что есть сейчас

- **Карта мира** (`WorldMap`, `MapScreen`) — как Xaero's World Map: клиент раскрашивает каждый полученный чанк (`WorldMap.scan`,
  `MapColors`), хранит регионы 512 × 512 (`MapRegion`) и уровни отдаления (`MapPyramid`) в
  `.minecraft/halgventmod/map/<мир>/<измерение>/`. Неразведанное — чёрное. Вид собирает `MapStyle` (основы Ванильная,
  Пергамент, Гравюра, Атлас + ползунки; по умолчанию Пергамент; хранится в `map_style.json`).
- **Инструменты внизу по центру**: «Рука» (компас), «Карандаш» (перо), «Стиль» (картина). Настройки карандаша и стиля — боковая
  панель справа (`MapSidePanel`). Правый клик по карте — меню: метка, надпись, телепорт (админ), точка, точка появления (админ в творческом).
- **Метки** (`Waypoint`, `Waypoints`) — личные, `waypoints.json` в папке карты, видны в мире и на компасе; ставятся через окно
  `WaypointEditScreen` (имя, значок, цвет, координаты, «на компасе»). Клавиша B — метка там, где стоит игрок.
- **Карандаш** (`MapDrawing`) — личный прозрачный слой по пикселю на блок, отмена Ctrl+Z.
- **Надписи** (`MapText`, `MapTexts`, `MapTextEditor`, `MapTextEditScreen`) — личные, `texts.json` в папке карты.
- **Точки карты** (`MapPoint`, `MapPoints`): тип LOCATION (место с границей: круг или многоугольник) и SPAWN. Игрок открывает место,
  зайдя в границу (`PointDiscovery`, проверка раз в 10 тиков). У места есть `hiddenIcon`, `hoverText`, `described`, `banner`,
  `description`, `info`. Открытая точка с описанием кликается и показывает `PointInfoPanel` слева.
- **Отряд** на карте — `SquadMarkers.clientMembers`, рисует `MapScreen.renderSquad`.

## 2. Что получится

Три окна карты вместо одного:

| Окно | Кто видит | Что это |
|---|---|---|
| **Карта локации** (`LocationMapScreen`) | Все | Настоящая карта одной локации: лист на столе, обрезанный по границе локации. Изведанная — целиком, неизведанная — туман и «Локация неизведана». |
| **Глобальная карта** (`GlobalMapScreen`) | Все | Нарисованная карта Хальгвента в 3D, шесть регионов, два масштаба: «весь Хальгвент» и «фокус на регионе». |
| **Техническая карта** (нынешний `MapScreen`, переделанный) | Только администрация | Настоящий мир без обрезки и тумана, поиск локаций, расширенные инструменты, слои. |

Переходы:

```
Игра ──M (в локации)──────────────► Карта локации ──«Хальгвент» / отдаление──► Регион в фокусе
  └──M (вне локации, запасной)─────────────────────────────────────────────► Регион в фокусе
Регион в фокусе ──Esc / ПКМ / отдаление──► Весь Хальгвент ──наведение + ЛКМ по региону──► Регион в фокусе
Регион в фокусе ──камера ушла за край──► соседний регион в фокусе (или упор в край, если там пусто)
Регион в фокусе ──ЛКМ по точке──► Окно локации ──«Открыть карту»──► Карта локации (любой локации, откуда угодно)
Администрация: M ──► Техническая карта ──«Как видит игрок»──► Карта локации выбранной локации
```

**Решения Bynelog (26.10.2026), которые нельзя менять без него:**

1. **Надписей в моде больше нет совсем** — ни у игроков, ни у администрации. Уже сделанные удаляются при обновлении мода.
2. **Стиля карты больше нет**: выбор основы и ползунки убираются, карта рисуется одним стилем (нынешний по умолчанию — `Base.PARCHMENT`).
3. Настройки инструмента (тип метки, тип рисования карандашом и т. п.) — **ПКМ по иконке инструмента** в нижней панели.
   **Правая панель — только слои**, никаких настроек инструментов.
4. **Метка ставится без окна**: ЛКМ ставит метку выбранного типа, под ней появляется небольшое поле, игрок печатает название
   и жмёт Enter.
5. Игрок **видит себя и своих соотрядников** на карте локации.
6. Карта локации **обновляется сама**: снимок сервера плюс то, что игрок видит рядом.
7. Игрок **не может оказаться вне локации**; на всякий случай M вне локации открывает глобальную карту.
8. Игрок **может открыть карту любой локации, где бы он ни был**. Неизведанная откроется тем же туманом и надписью
   «Локация неизведана».
9. Камера глобальной карты **вращается только вокруг вертикали**, наклон постоянный.
10. **Маршруты видит только администрация** — они нужны для работы НПС.
11. Рисунок глобальной карты **уже есть** у Bynelog. Регионов шесть: **Вессен, Перевал, Валленбург, Треверон, Розенмайр, Лебенскап**.

## Этап 1. Снимок карты локации

Цель: игрок, открывший локацию, сразу получает её полную карту, даже там, где сам не был. Неоткрытая локация на клиент не попадает
вообще (её нельзя вытащить из файлов).

### 1.1 Выборка столбца — общий код

Вынеси из `WorldMap` (`surface`, `visible`, проход сквозь воду из `waterColor`) в общий класс `map/ColumnSampler` (пакет
`com.nrdhvnstd.halgventmod.map`, не `client`): по `LevelChunk` и (x, z) он отдаёт

| Поле | Тип | Смысл |
|---|---|---|
| `state` | `BlockState` | Верхний видимый блок (для воды — вода) |
| `height` | int | Его высота; `Integer.MIN_VALUE` — столбец пуст |
| `floor` | `BlockState` | Дно под водой, `null` — воды нет |
| `depth` | int | Глубина воды в блоках (0 — воды нет), не больше 255 |
| `biome` | `ResourceLocation` | Биом на высоте поверхности (берётся по середине клетки 4 × 4, как сейчас) |

Цвет `ColumnSampler` не считает: сервер не знает текстур (Conquest Reforged). `WorldMap.scan` после выноса ведёт себя как раньше.
Учесть измерения с потолком (как сейчас в `surface`).

### 1.2 Снимок на сервере

- Новый класс `point/LocationMaps` (сервер). Снимок запускает администратор: кнопка «Снять карту локации» на технической карте
  (этап 5; до него — пункт в нынешнем меню правого клика по точке) и команда `/point capture <id>` (подсказка id по точкам,
  только `Permissions.ADMIN_LEVEL`).
- Область — прямоугольник вокруг границы точки (`MapPoint.contains` даёт форму; для круга — квадрат `2r × 2r`).
  **Предел — 2048 × 2048 блоков ⚠️**; больше — ошибка в чат «[Карта] Локация слишком большая для снимка».
- Читать **только уже сгенерированные чанки**, ничего не генерировать. Не больше `CAPTURE_CHUNKS_PER_TICK = 8 ⚠️` чанков за
  серверный тик; задача живёт между тиками (`ServerTickEvent.Post`). Несгенерированный чанк — столбцы «неизвестно».
- Ход снимка — администратору раз в секунду (`LocationCaptureProgressPayload`, проценты), в конце — «[Карта] Снимок «<имя>» готов».
- Одновременно — одна задача на сервер; вторая команда — «уже идёт снимок «<имя>»».
- После снимка у точки растёт `mapVersion` (новое поле `MapPoint`, int, по умолчанию 0 — «не снят»; дописать в `copy`, сеть,
  `save`/`load`, старые миры грузятся с 0), точки рассылаются как обычно.

### 1.3 Файл снимка

`<мир>/data/halgventmod/location_maps/<id точки>.bin` — отдельный файл, **не** `SavedData` (сотни КБ). Запись через временный файл,
как в `MapStorage`. Всё внутри — gzip (`DataOutputStream`):

```
int    MAGIC = 'HGLM'
int    FORMAT = 1
int    pointId, mapVersion
int    minX, minZ, width, height          // в блоках
int    blockCount; blockCount × UTF        // палитра: BlockStateParser.serialize(state); номер 0 — «неизвестно»
int    biomeCount; biomeCount × UTF        // палитра биомов: ResourceLocation; номер 0 — «неизвестно»
width×height × { varint block, short height, byte depth, [varint floor если depth > 0] }   // построчно по z, потом по x
(width/4)×(height/4) × varint biome                                                          // клетки 4 × 4
```

Столбцы вне границы точки пишутся как «неизвестно» (0) — так на диске и в сети нет ничего за границей локации.

### 1.4 Сеть

| Пакет | Направление | Содержание |
|---|---|---|
| `LocationMapRequestPayload` | клиент → сервер | id точки, версия в кэше клиента |
| `LocationMapPartPayload` | сервер → клиент | id, версия, номер части, всего частей, `byte[]` (кусок gzip-файла) |
| `LocationCapturePayload` | клиент → сервер | id точки — запустить снимок (сервер проверяет `MapPoints.canEdit`) |
| `LocationCaptureProgressPayload` | сервер → клиент | id, проценты (0–100) |

- Части по `PART_BYTES = 256 * 1024 ⚠️`, не больше `PARTS_PER_TICK = 2 ⚠️` на игрока за тик.
- Сервер отвечает на запрос, **только если точка открыта у игрока** (`PointDiscovery`) **или он администратор**, и версия у клиента
  старше. Иначе молчит.
- Клиент сам просит снимки: при входе (по `PointsSyncPayload` + `PointsDiscoveredPayload` — для каждой открытой точки, у которой
  `mapVersion` больше версии в кэше) и сразу после открытия новой точки. Администратор — для всех точек.

### 1.5 Клиент: кэш и заливка в карту

- Кэш: `.minecraft/halgventmod/map/<мир>/locations/<id>.bin` (тот же файл, что на сервере). Есть файл нужной версии — не качать.
- Заливка — в фоне (`MapWorker`): столбцы снимка раскрашиваются `MapColors.color(...)` и пишутся в `MapRegion` тем же
  `region.set(...)`/`setBiome(...)`, что и при сканировании; вода — как в `waterColor` (дно + вода по глубине). Для оттенков биома
  нужен вариант `ChunkTints`, который берёт биомы из снимка, а не из загруженных чанков (`SnapshotTints`).
- Новая версия снимка перезаписывает пиксели внутри границы целиком. Дальше карта живёт как сейчас: чанки рядом с игроком
  пересматриваются, и свежие постройки попадают на неё сами (решение 6).
- Уровни отдаления после заливки перестраивает `MapPyramid.update`, как после обычной записи регионов.

**Проверка:** администратор снимает локацию 512 × 512; второй игрок, не бывавший там, заходит в границу — сразу видит всю локацию
на карте; до входа в границу файла снимка у него в кэше нет; повторный вход в мир снимок не качает; после повторного снимка
(перестроили дом) у второго игрока новая версия. Подделанный запрос неоткрытой точки — сервер молчит.

## Этап 2. Окно карты локации (`LocationMapScreen`)

```
┌──────────────────────────── стол (текстура) ────────────────────────────┐
│ [Хальгвент]                       Название локации                       │
│        ┌────────────────────────── лист ───────────────────────┐ ┌─────┐ │
│        │   пустая бумага                                        │ │Слои │ │
│        │      ╭──────── граница локации ────────╮               │ │ ☑ К │ │
│        │      │   настоящая карта (снимок +     │               │ │ ☑ М │ │
│        │      │   своё), метки, карандаш,       │               │ │ ☑ О │ │
│        │      │   ▲ игрок, ▲ соотрядники        │               │ └─────┘ │
│        │      ╰─────────────────────────────────╯               │         │
│        └────────────────────────────────────────────────────────┘         │
│                         [ Рука ][ Карандаш ][ Метка ]                     │
└─────────────────────────────────────────────────────────────────────────┘
```

- **Открытие.** M в игре: игрок внутри локации — её карта; внутри нескольких (границы пересеклись) — последней открытой
  [по умолчанию]; вне всех — глобальная карта (решение 7, этап 3). Администратор по M открывает техническую карту (этап 5).
  `LocationMapScreen` открывается и для любой другой локации — из окна локации на глобальной карте (решение 8).
- **Стол и лист.** Фон — текстура стола (заглушка). Лист — прямоугольник вокруг границы локации плюс поля `SHEET_MARGIN = 24 ⚠️`
  блока, с рамкой из 9 частей и тенью. Внутри листа карта рисуется **тем же кодом, что сейчас** (`renderRegions`, уровни
  отдаления), а всё вне границы локации закрывается пустой бумагой заливкой по строкам (как `PointShapes`, только снаружи
  фигуры). По границе — неровный край.
- **Камера** упирается в лист: середину экрана нельзя увести за лист, отдалить — не дальше, чем лист целиком на экране;
  ещё шаг колёсика наружу — переход на глобальную карту в фокусе на регионе этой локации. Приблизить — как сейчас (`MAX_ZOOM`).
  Пробел — к себе (если игрок в этой локации).
- **Туман.** Неизведанная локация — тот же лист, внутри границы — текстура тумана, по центру «Локация неизведана» (цвет заголовка).
  Данных под туманом у клиента нет. Внутри изведанной локации столбцы «неизвестно» тоже рисуются туманом, а не чёрным.
- **Игрок и отряд** — как сейчас (`renderPlayer`, `renderSquad`); соотрядники — по тому, что уже присылает сервер (`SquadMarkers`).
  Игрок рисуется, только если он в этой локации.
- **Нижняя панель** — три инструмента: Рука, Карандаш, Метка (иконки — заглушки; до них предметы: компас, перо, флаг).
  **ЛКМ по иконке** — выбрать инструмент. **ПКМ по иконке** — над ней всплывает маленькая панель настроек этого инструмента;
  закрывается кликом мимо или Esc.
  - **Рука** — тащить карту, колёсико — масштаб, наведение на метку — подсказка (имя, координаты, расстояние). Настроек нет.
  - **Карандаш** — нынешний `MapDrawing`: ЛКМ рисует, ПКМ стирает, средняя тащит карту, Ctrl+Z — отмена. Рисовать — только внутри
    листа. ПКМ по иконке — чернила (`MapScreen.INKS`), толщина, «Очистить» (с подтверждением, как сейчас).
  - **Метка** — ПКМ по иконке: значок (`MapIcon`), цвет флага (красители) и «На компасе» [по умолчанию] — это «тип» новых меток,
    помнится между открытиями. **ЛКМ по карте сразу ставит метку этого типа, без окна**; под меткой появляется небольшое поле
    (ширина ≈ 100 ⚠️ единиц GUI), фокус в нём, игрок печатает название и жмёт Enter. [По умолчанию] Enter с пустым полем — метка
    без названия; Esc — метка не ставится. Двойной клик по метке — то же поле для переименования; ПКМ по метке — удалить.
    Высота метки — из карты (`standingY`). Клавиша B в игре — метка выбранного типа там, где стоит игрок, без окна.
- **Правая панель — только слои** (решение 3): галочки «Карандаш», «Метка», «Отряд» [по умолчанию]. Снятая галочка не рисует слой
  и выключает наведение на его элементы. Состояние помнится между открытиями.
- **Меню правого клика по карте у игрока больше нет.** `WaypointEditScreen` при установке метки не открывается (класс можно
  оставить для правки координат из технической карты — на твоё усмотрение, скажи в плане).
- Точки-локации на карте локации не рисуются (лист и так одна локация); соседние локации — нет [по умолчанию].
- **Удаление стиля** (решение 2): убрать инструмент «Стиль», `MapScreen.stylePanel`, ползунки и выбор основы; `MapStyle` оставить
  как внутренний расчёт цвета с фиксированными значениями `Base.PARCHMENT`. `map_style.json` при запуске удалить, если он есть.
  Выключатель подписей биомов из панели стиля уходит в слои технической карты (этап 5).
- **Удаление надписей** (решение 1): удалить `MapText`, `MapTexts`, `MapTextEditor`, `MapTextEditScreen`, их отрисовку, пункты меню
  и переводы. При входе в мир клиент удаляет `texts.json` из папки карты этого мира и измерения (файл был только у клиента;
  на сервере чистить нечего).

**Проверка:** M в локации открывает её лист; камеру нельзя увести за лист; за границей — пустая бумага; неизведанная — туман
и надпись; метка ставится одним кликом, имя вводится под ней, Enter/Esc работают; ПКМ по иконкам открывает настройки, правая
панель — только слои; игрок и соотрядник видны; старые `texts.json` и `map_style.json` исчезли, карта не упала.

## Этап 3. Глобальная карта: рисунок, регионы, камера (`GlobalMapScreen`)

### 3.1 Ресурсы

В `assets/halgventmod/textures/gui/global_map/`:

- `map_<col>_<row>.png` — рисунок Хальгвента, нарезанный кусками по `TILE = 2048` пикселей (бо́льшие текстуры тянут не все видеокарты).
  Полный размер рисунка ⚠️ — уточнить по файлу Bynelog.
- `regions.png` — маска того же размера или вдвое меньше: каждый регион залит своим цветом, **без сглаживания краёв**; море и
  пустота — чёрные `#000000`.
- `regions.json` — `{"size": [w, h], "regions": [{"id": "vessen", "color": "#RRGGBB"}, ...]}`. Названия и описания — переводы
  `region.halgventmod.<id>` и `region.halgventmod.<id>.description` через `ModLanguageProvider`.

Регионы и их id: Вессен `vessen`, Перевал `pereval`, Валленбург `wallenburg`, Треверон `treveron`, Розенмайр `rosenmair`,
Лебенскап `lebenskap` (id — предложение, латиницей; поправить, если Bynelog скажет иначе).

**До рисунка Bynelog** — заглушка: однотонный пергамент 2048 × 1024 и маска с шестью прямоугольниками. Код не должен зависеть от
размера рисунка.

### 3.2 Загрузка

При загрузке ресурсов (`ResourceManagerReloadListener`): прочитать маску в память (`int[]` id региона на пиксель), для каждого
региона — прямоугольник, вырезанный из рисунка кусок с прозрачностью по маске (`DynamicTexture`) и текстура контура (пиксели
маски, у которых сосед — другой регион). Это делается один раз, не каждый кадр.

### 3.3 Камера и отрисовка

- На время отрисовки карты окно ставит свою перспективную проекцию (`RenderSystem.backupProjectionMatrix`,
  `setProjectionMatrix(new Matrix4f().perspective(...), VertexSorting.DISTANCE_TO_ORIGIN)`, рисование `Tesselator`/`BufferBuilder`
  с `position_tex`), потом возвращает обычную (`restoreProjectionMatrix`) — интерфейс поверх рисуется обычным `GuiGraphics`.
- Рисунок лежит плоскостью. Камера смотрит строго сверху (`TILT = 90°`, решение Bynelog 2026-10-27); **вращение только вокруг вертикали** (решение 9):
  ПКМ-перетаскивание по горизонтали и клавиши Q / E. ЛКМ-перетаскивание — сдвиг. Колёсико — приблизить / отдалить в пределах
  масштаба (см. ниже); отдаление дальше предела — смена масштаба.
- Что под курсором: луч от мыши пересекается с плоскостью → пиксель рисунка → маска / точки.
- Переходы между масштабами — плавный пролёт камеры `FLY_SECONDS = 0.4 ⚠️`.

### 3.4 Масштаб «Весь Хальгвент»

- Виден весь рисунок, все регионы с границами (контуры) и **только главные локации** (`MapPoint.major`, этап 4).
- Наведение на регион: его вырезанный кусок рисуется **поднятым** над плоскостью на `LIFT = 6 ⚠️` единиц, под ним тень, контур
  светится (цвет заголовка), рядом — название региона. Подъём и опускание — за `LIFT_SECONDS = 0.15 ⚠️`, с плавным ходом.
  Как в Helldivers 2.
- ЛКМ по региону — пролёт камеры в фокус на этом регионе.

### 3.5 Масштаб «Фокус на регионе»

- Регион занимает экран (по его прямоугольнику с полями), остальные затемнены (`FOCUS_DIM = 0.55 ⚠️`).
- Видны **все** локации региона (этап 4).
- Сдвиг камеры проверяет маску под серединой экрана:
  - середина ушла в **другой регион** — фокус плавно переезжает на него;
  - середина ушла в **пустоту** (чёрное в маске, край рисунка) — сдвиг в эту сторону не принимается (камера «упирается»),
    вдоль края можно скользить.
- Выход на «Весь Хальгвент» — Esc, ПКМ-клик (без перетаскивания, сдвиг ≤ 3 px как `CLICK_SLOP`) или отдаление колёсиком.
  Esc на «Весь Хальгвент» закрывает карту.
- **Какой регион в фокусе при открытии:** из карты локации — регион этой локации; M вне локации (запасной случай) — регион
  ближайшей локации этого измерения [по умолчанию]; локации без места на рисунке — «Весь Хальгвент».

**Проверка:** на заглушке шесть регионов поднимаются и светятся под курсором; клик — фокус; сдвиг в соседний регион переводит
фокус, в море — упор; Q / E и ПКМ вращают, наклон не меняется; Esc / отдаление — обратно; интерфейс поверх не поехал; FPS на
слабой машине не падает заметно.

## Этап 4. Локации на глобальной карте и окно локации

### 4.1 Новые поля `MapPoint`

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `globalX`, `globalY` | int | `-1` | Место на рисунке в пикселях; `-1` — не поставлена на глобальную карту |
| `major` | boolean | `false` | Главная локация: видна и на «Весь Хальгвент» |

Дописать в `copy`, сеть, `save`/`load` (старые миры грузятся), `valid()` (`-1` или в пределах размера рисунка — размер сервер не
знает, поэтому проверять только `≥ -1` и `≤ 16384 ⚠️`). **Регион точки не хранится**: он берётся из маски под `(globalX, globalY)`.
Рисунок не в масштабе мира, поэтому место ставится руками.

### 4.2 Размещение администрацией

В `PointEditScreen` (левая колонка, под значками): кнопка «На глобальной карте…» и галочка «Главная локация».
Кнопка открывает `GlobalMapScreen` в режиме выбора места: «Весь Хальгвент», ЛКМ ставит точку, Enter / «Готово» возвращает
координаты в окно точки, Esc — без изменений. Под кнопкой — название региона, в который попала точка, или «не на карте».

### 4.3 Точки на глобальной карте

- Точка — спрайт (заглушка, 32 × 32: обычная, главная, неоткрытая) **стоит** на плоскости (повёрнут к камере), под ней — название.
- Неоткрытая (`MapPoints.clientDiscovered`) — значок неоткрытой и **без названия**, как сейчас на карте и компасе.
- Наведение: точка поднимается и подсвечивается (как регион в 3.4).
- ЛКМ — окно локации.

### 4.4 Окно локации

Поверх глобальной карты, по центру, ширина `min(280, 45 % ширины) ⚠️`, высота — сколько влезет:

```
┌──────────────────────────────────────┐
│           Название локации       [×] │   неоткрытая: «Неизвестное место»
│ ┌──────────────────────────────────┐ │
│ │                                  │ │   квадратная миниатюра карты локации;
│ │   миниатюра карты локации        │ │   неизведанная — туман и «Локация неизведана»
│ │                                  │ │
│ └──────────────────────────────────┘ │
│ Сведения: Владелец: ... (ключ тусклым)│▐  info, затем description;
│ Описание с переносом строк ...        │▐  прокрутка колёсиком, ползунок — если не влезло
│                     [ Открыть карту ] │
└──────────────────────────────────────┘
```

- Тексты: открытая — `info` и `description` (строка «Слово: текст» рисует слово тусклым, как в `PointInfoPanel`);
  неоткрытая — `hoverText`.
- Миниатюра — квадрат по большей стороне листа, строится один раз из уровня отдаления (`MapPyramid`) по прямоугольнику листа и
  обрезается по границе; кэшируется до новой версии снимка.
- **«Открыть карту»** — у любой локации, где бы игрок ни был (решение 8): `LocationMapScreen` этой локации; неизведанная — лист
  с туманом. Esc в карте локации, открытой так, возвращает на глобальную карту.
- Закрыть окно — [×], Esc, клик мимо.

**Проверка:** администратор ставит точку на рисунке, регион определяется сам; главная видна на «Весь Хальгвент», обычная — только
в фокусе; неоткрытая без названия; окно у открытой и неоткрытой; длинное описание листается; «Открыть карту» открывает и изведанную,
и неизведанную; второй игрок видит изменения сразу.

## Этап 5. Техническая карта администрации

Нынешний `MapScreen` переделать в техническую карту. Открывается по M только у `Permissions.isAdmin`; правка — только при
`MapPoints.canEdit` (в творческом), без него инструменты правки серые с подсказкой «Нужен творческий режим».
Мир показывается **как есть**: без обрезки, без тумана, со всеми снимками и всем, что администратор разведал сам.

```
┌ [◀] [ Название локации______________ ] [▶]  [Снять карту локации ▓▓▓░ 60%]  [Как видит игрок] ┐
│                                                                                    ┌────────┐ │
│                          настоящий мир                                             │ Слои   │ │
│                                                                                    │ ☑ Каран│ │
│                                                                                    │ ☑ Метка│ │
│                                                                                    │ ☑ Точка│ │
│                                                                                    │ ☑ Маршр│ │
│                                                                                    │ ☑ НПС  │ │
│                                                                                    │ ☑ Биомы│ │
│                                                                                    │ ☑ Отряд│ │
│                                                                                    └────────┘ │
│                   биом и координаты под курсором                                              │
│                 [ Рука ][ Карандаш ][ Метка ][ Точка ][ Маршрут ]                             │
└───────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Сверху** — поле «Название локации»: ввод фильтрует локации (`Kind.LOCATION`) по подстроке, под полем список подсказок
  (до 8 ⚠️), Enter или клик — камера летит к локации и подгоняет масштаб под её границу. **◀ ▶** перебирают локации по алфавиту
  по кругу, поле показывает имя текущей. Справа — «Снять карту локации» (этап 1, с полоской хода; серая, если локация не выбрана)
  и «Как видит игрок» — открывает `LocationMapScreen` выбранной локации.
- **Снизу** — пять инструментов (надписей нет — решение 1). ЛКМ по иконке — выбрать, ПКМ — настройки над иконкой (решение 3):

| Инструмент | ЛКМ по карте | ПКМ по иконке |
|---|---|---|
| Рука | Тащить карту; ПКМ по карте — телепорт сюда (`MapTeleportPayload`) | — |
| Карандаш | Как у игрока | Чернила, толщина, «Очистить» |
| Метка | Как у игрока: метка выбранного типа + поле названия | Значок, цвет, «На компасе» |
| Точка | По пустому — новая локация: граница (`PointBoundsEditor`), потом `PointEditScreen`; по точке — `PointEditScreen`; Shift+ЛКМ по пустому — точка появления (`SpawnPointEditScreen`); ПКМ по точке — «Изменить границы» | — |
| Маршрут | Этап 6 | — (цвет — в окне маршрута) |

- Меню правого клика по карте удалить; всё, что в нём было, теперь в инструментах.
- **Справа — только слои** (решение 3): Карандаш, Метка, Точка, Маршрут, НПС, плюс Биомы (подписи биомов, бывший выключатель из
  стиля) и Отряд. **НПС** — строка есть, слой пока пустой (НПС в моде ещё нет; оставить точку расширения). Состояние галочек
  помнится между открытиями.
- Боковая панель `MapSidePanel` для настроек больше не нужна (всё — во всплывающих панелях над иконками); удалить или переделать
  во всплывающую — на твоё усмотрение.

**Проверка:** поиск и стрелки перелетают к локациям; снимок запускается и идёт полоска; «Как видит игрок» показывает лист;
все пять инструментов и ПКМ-настройки; каждый слой включается и выключается; не-администратор техническую карту не открывает
и подделанным пакетом ничего не меняет.

## Этап 6. Маршруты

Маршруты — ломаные для будущих НПС. **Видит только администрация** (решение 10).

- **Данные:** `point/MapRoute` — `id`, `name` (≤ 32), `dimension`, `xs`/`zs` (вершины в блоках, от 2 до `MAX_ROUTE_POINTS = 256 ⚠️`),
  `color` (ARGB). `point/MapRoutes extends SavedData` по образцу `MapPoints`.
- **Рассылка — только администрации**, как точки появления (`seesSpawns` / `SPAWN_VIEWERS`): при входе, после правки, при выдаче
  или снятии прав. Пакеты `RoutesSyncPayload` (сервер → админы) и `RouteEditPayload` (CREATE / UPDATE / DELETE, сервер проверяет
  `MapPoints.canEdit`).
- **Рисование** (как описал Bynelog):
  1. ЛКМ по иконке «Маршрут» — инструмент выбран, можно начать маршрут.
  2. Первый ЛКМ по карте — начало маршрута. Каждый следующий ЛКМ — точка маршрута. Между точками — прямые линии; от последней
     точки до курсора — линия-предпросмотр.
  3. **Enter** — завершить: внутри технической карты открывается небольшое окно (не отдельный экран): поле «Название»
     и выбор цвета, кнопки «Сохранить» / «Отмена». **Цвет по умолчанию — светло-оранжевый** `ROUTE_DEFAULT = 0xFFFFB060 ⚠️`.
  4. **ПКМ или Esc** во время рисования — прекратить, ничего не сохраняя.
  - Меньше двух точек — Enter ничего не делает.
- **Правка готового** [по умолчанию]: вершины тянутся мышью (как в `PointBoundsEditor`), двойной клик по линии — то же окно
  (название, цвет), Delete при выделенном маршруте — удалить (с подтверждением).
- Название маршрута — подписью у начала, тусклым, только на технической карте.
- Слой «Маршрут» в правой панели прячет все маршруты.

**Проверка:** нарисовать маршрут из 5 точек, Enter — окно, цвет по умолчанию светло-оранжевый, сохранить; ПКМ и Esc отменяют;
перезапуск сервера — маршрут на месте; второй администратор видит его сразу; обычный игрок не получает маршрутов вообще
(проверить, что пакет ему не уходит).
