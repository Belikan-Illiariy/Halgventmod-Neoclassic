# Броня — техническое задание

Документ для реализации системы брони в моде **Halgventmod: Neoclassic**. Концепт утверждён; здесь собрано всё, что решено, и то, что ещё открыто.

Шаблоны развёрток лежат рядом, в папке `templates/`.

---

## 0. Как работать с этим заданием

1. **Сначала изучи проект** — пакеты, билдер предметов в `ModItems`, датаген, сеть, вложения (attachments), компоненты. Задание опирается на то, что уже есть.
2. **Составь план по этапам** (раздел 12): какие классы появятся, какие файлы изменятся. Покажи план и дождись одобрения.
3. **Реализуй по одному этапу.** После каждого — сборка (`./gradlew build`), `runData`, проверка в игре на проверочном наборе вещей.
4. **Решения, которые трудно отменить** — формат моделей, новые зависимости, изменение формата сохранений — сначала обсуди.

**Не делать:**
- рецепты и крафты — ими займёмся отдельно;
- числа защиты и механику урона — её дизайн ещё не готов (этап 7);
- библиотеку Curios — инвентарь свой (раздел 10).

**Соглашения проекта:**
- все предметы объявляются в `ModItems` через билдер `item(...)`; отдельные классы — только для поведения (наследники `Item`), не для объявления предметов по фичам;
- комментарии в коде — на русском, короткие и понятные;
- переводы — только через `ModLanguageProvider` (датаген), модели предметов — через `ModItemModelProvider`;
- все настраиваемые числа — именованные константы в начале класса.

## 2. Слоты

Вместо четырёх ванильных слотов брони — двенадцать:

| Часть тела | Слоты |
|---|---|
| Голова | Накидка · Шлем · Койф · Подшлемник |
| Туловище | Кисти · Нагрудник · Кольчуга · Поддоспех |
| Ноги | Обувь · Поножи · Шоссы · Штаны |

### Накидка

Особый слот. Виды:
- **капюшон** — только голова;
- **плащ** — спина и плечи, развевается при движении (как ванильный плащ);
- **плащ с капюшоном** — и то и другое.

**Капюшон лежит поверх шлема** и совместим не со всеми шлемами:
- совместимость — свойство шлема (`hoodCompatible`);
- совместимы небольшие шлемы без выступающих деталей (колпаки, цервельер);
- несовместимы крупные и с выступающими деталями (топфхельм, хундсгугель с забралом, капеллина с полями, шлемы с рогами и гребнями);
- надеть капюшон поверх несовместимого шлема нельзя → над хотбаром «Капюшон не надеть поверх этого шлема»;
- надеть несовместимый шлем, когда капюшон надет, нельзя → «Сначала снимите капюшон»;
- правило касается только накидок с капюшоном; плащ без капюшона совместим с любым шлемом.

## 3. Отрисовка: всё в одной плоскости

Броня **не добавляет толщины**. Основная часть любой вещи (латы тоже) лежит в той же плоскости, что и ванильная броня. Плоскостей две, как в ванилле:

| Плоскость | Раздутие | Что в ней |
|---|---|---|
| **Ноги** (как ванильный `layer_2`) | как у ванильных поножей | штаны, шоссы, поножи, обувь; плюс **пояс** — низ туловища |
| **Внешняя** (как ванильный `layer_1`) | как у ванильного нагрудника | голова, туловище, руки (включая кисти) |

Внешняя плоскость лежит поверх плоскости ног, поэтому вещи туловища сами ложатся поверх пояса штанов.

**Правила, без которых будет мерцание (z-fighting):**
1. Основная часть всех вещей одной плоскости — **одна и та же оболочка** с одинаковой геометрией. Вещи различаются только текстурой. Короткий рукав — это прозрачные пиксели, а не короткий кубик.
2. Пиксели **либо непрозрачные, либо полностью прозрачные** (cutout).
3. Всё, что выступает за плоскость, — **отдельная модель** (раздел 8).

**Дополнительно:**
- второй слой скина игрока (куртка, рукава, штанины, шапка) на участках, закрытых бронёй, скрывается, чтобы не просвечивать;
- в виде от первого лица на руках видны рукава и перчатки.

## 5. Склейка текстур (compositing)

Слои не рисуются каждый отдельным проходом. Клиент заранее склеивает надетые вещи в **одну текстуру на плоскость** и рисует её за один проход.

**Алгоритм:**
1. Сервер синхронизирует клиентам, что надето на каждом игроке (это нужно для отрисовки в любом случае).
2. Клиент составляет **рецепт образа** — упорядоченный список: вещь + её данные (цвет, украшения) для каждой надетой вещи плоскости.
3. Ключ кэша — рецепт (или его хэш). Если склейка по такому рецепту уже есть — используется она. Одинаково одетые игроки делят одну текстуру.
4. Если нет — на пустой холст по порядку из раздела 4 переносятся текстуры вещей: непрозрачные пиксели перекрывают нижние, прозрачные пропускают. Для каждой вещи внутри: основа (с окраской) → украшения (раздел 11) → `_overlay`.
5. Результат загружается как динамическая текстура (`NativeImage` → `DynamicTexture`) под сгенерированным `ResourceLocation`.
6. Отрисовка: две оболочки (ноги и внешняя) с этими текстурами + выступающие модели отдельно.

**Хозяйство:**
- неиспользуемые склейки освобождаются через несколько минут (освобождать и GPU-текстуру);
- перезагрузка ресурсов (F3+T) очищает кэш;
- все текстуры брони — одного размера (**128×64**); если попалась 64×32 — увеличить без сглаживания (nearest neighbor);
- склейка — **только клиент**, сервер в ней не участвует.

Пример ванильного родственника приёма — отделка брони (armor trims): тот же меш рисуется повторно с другой текстурой.

## 6. Окраска

- Окрашиваемая вещь рисуется **в оттенках серого**; цвет хранится в компоненте предмета и применяется при склейке. Способов два:
  - **ткань** (`.dyeable()`) — умножение, складки и стёжка сохраняются;
  - **эмаль** (`.enamel()`, металл) — три файла: `<id>.png` (сталь в цвете, не красится), `<id>_enamel.png` (серый слой эмали, сам не показывается) и `<id>_overlay.png`. Покрашенная вещь: сталь → слой эмали, окрашенный «перекрытием» (Overlay: серый 128 = чистый цвет, темнее — тень, светлее — блик) → overlay. Цвета эмали — 14 штук (`armor/EnamelColor.java`): красный `734040`, зелёный `668553`, синий `637097`, фиолетовый `9f8baa`, пурпурный `8c6586`, оранжевый `a0835a`, жёлтый `b0a76a`, бирюзовый `8daeaa`, белый `e6e6e6`, серый `959595`, светло-серый `b9b9b9`, чёрный `636363`, коричневый `7e736c`, голубой `a1b1c7`. Непокрашенная: сталь → overlay. У выступающих деталей так же (`<id>_<деталь>_enamel.png`). Накидкам эмаль запрещена.
- Неокрашиваемые детали (пряжки, шнуровка, кант, ремни) — отдельный файл `<id>_overlay.png`, накладывается поверх, не красится.
- Одна текстура → сколько угодно цветов. Отдельных текстур под цвета нет.
- **Открыто:** набор цветов — 16 ванильных красителей или свои средневековые (вайда, марена, резеда, кермес). Систему делать так, чтобы цвет был произвольным RGB, а набор красителей задавался отдельно.

## 7. Текстуры и файлы

### Разметка

Текстура вещи — **полная развёртка своей плоскости**, 128×64 (двойное разрешение ванильной развёртки брони 64×32; 1 ванильный пиксель = 2×2 пикселя). Вещь рисует только свои участки, остальное прозрачно. Полная разметка (а не обрезка по слоту) выбрана потому, что тогда узоры и украшения (раздел 11) подходят ко всем вещам плоскости сразу.

Шаблоны: `templates/armor_outer_template.png`, `templates/armor_legs_template.png` (и превью с подписями).

| Плоскость | Участки (по высоте конечности 12 ванильных пикселей) |
|---|---|
| Внешняя | голова; туловище; руки: плечо (верхние 4), предплечье (5), **кисть** (нижние 3 + низ руки) |
| Ноги | пояс (участок туловища); ноги: бедро (верхние 5), голень (4), **стопа** (нижние 3 + подошва) |

- Перчатки рисуются на кисти, обувь — на стопе; рукава и поножи заканчиваются выше. Остальные границы — ориентир.
- Левые конечности — зеркальная копия правых (как в ванильной развёртке).
- Не используются: дополнительный слой головы (hat), ноги во внешней плоскости (в ванилле там ботинки; у нас обувь в плоскости ног), голова и руки в плоскости ног.

### Файлы одной вещи

```
textures/armor/<слот>/<id>.png             плоская текстура (окрашиваемая — в оттенках серого)
textures/armor/<слот>/<id>_overlay.png     неокрашиваемые детали (если вещь красится)
models/armor/<слот>/<id>_<деталь>          модель выступающих деталей (если есть)
textures/armor/<слот>/<id>_<деталь>.png    текстура этой модели
textures/item/armor/<id>.png               иконка 32×32
```

Папки слотов: `helmet, coif, arming_cap, cloak, gloves, breastplate, mail, padding, boots, greaves, chausses, trousers` (имена на согласование).

## 8. Выступающие детали

- На плоской текстуре — то, что лежит на поверхности тела. **Всё, что торчит наружу**, — модель из **Blockbench** со своей текстурой.
- Модель крепится к части тела (голова, туловище, правая/левая рука, правая/левая нога) и движется вместе с ней.
- Рисуется после склейки, поверх неё.
- Деталь начинается от плоскости брони (на 1 ванильный пиксель снаружи тела). Грани модели **не должны лежать точно в плоскости** брони — сдвиг хотя бы на 0,1 пикселя.
- Нужны **свободные повороты** кубиков (изогнутые рога, наклонное забрало). **Формат модели — открытый вопрос:** предложи варианты (JSON-модели Java с ограничением поворотов, геометрия Bedrock `.geo.json` со своим загрузчиком, другое) и дождись решения.
- Подготовить **шаблон проекта Blockbench**: фигура игрока, полупрозрачная плоскость брони для ориентира, названные кости для крепления.

| Вещь | Плоско | Модель |
|---|---|---|
| Хундсгугель | колокол, заклёпки | забрало-«морда»; ось на висках (на будущее — поднять/опустить) |
| Топфхельм | горшок: щель, усиления, отверстия | рога, нашлемник |

| Поножи | основная пластина | наколенники |
| Плащ | — | сам плащ (своя модель и текстура) |

## 9. Описание вещи в коде

Предлагаемое расширение билдера `ModItems` (имена — на согласование):

```java
public static final DeferredItem<Item> HOUNSKULL = item("hounskull", "Хундсгугель", "Hounskull", Gender.M)
        .category(Category.ARMOR)
        .armor(ArmorSlot.HELMET)          // слот; из него — плоскость и порядок по умолчанию
        .armorModel("hounskull_visor")    // выступающая деталь (необязательно)
        .hoodCompatible(false)            // только для шлемов
        .kg(3.2)
        .lore("…", "…")
        .register();

public static final DeferredItem<Item> QUILTED_AKETON = item("quilted_aketon", "Акетон", "Aketon", Gender.M)
        .category(Category.ARMOR)
        .armor(ArmorSlot.PADDING)
        .dyeable()                        // основа в сером + _overlay
        .layerOrder(9)                    // необязательно: свой номер вместо номера слота
        .kg(2.5)
        .register();
```

- `ArmorSlot` — перечисление 12 слотов: плоскость, порядок по умолчанию, папка текстур, название слота для интерфейса.
- Плоская текстура находится по ID и слоту автоматически.
- Предмет брони стакается по 1.

## 10. Инвентарь

- **Свой**: 12 ячеек брони вокруг фигурки персонажа **вместо** четырёх ванильных. Ванильные слоты брони убрать.
- Хранение — вложение игрока на 12 ячеек; сохраняется; синхронизируется самому игроку и игрокам, которые его видят (для отрисовки).
- В ячейку кладётся только вещь своего слота; проверка правила «капюшон — шлем» (раздел 2).
- Shift+клик по вещи брони в инвентаре — надеть в её ячейку.
- Смерть: броня ведёт себя как инвентарь (с учётом `keepInventory`).
- Вес надетой брони учитывается системой веса.
- Фон окна — рисунок художника с местами под 12 ячеек (пока нет — временный).
- Иконки пустых ячеек — силуэты слотов (рисунки художника; пока нет — временные).

## 11. Кастомизация (поздний этап, но склейку сразу проектировать под неё)

Широкий редактор украшений — гораздо шире ванильного станка.

**Данные:** у вещи — компонент со **списком украшений** (до 12). Украшение: узор + место (для эмблем) + материал/цвет.

**Порядок внутри вещи при склейке:** основа (окрашенная) → украшения по порядку → `_overlay` (ремни и пряжки всегда сверху).

**Виды:**

| Вид | На чём | Материал | Как выглядит |
|---|---|---|---|
| Роспись | латы, шлемы | краска | плоский цвет поверх металла |
| Инкрустация | латы, шлемы | золото, серебро | узор, залитый текстурой металла с бликами (не плоским цветом) |
| Нашивка | акетоны, накидки, плащи | ткань, нить | цветной узор; стёжка ткани под ним видна |

**Узоры:**
- **на всю вещь** — полосы, шашки, кайма, перевязь, крест: маска в разметке плоскости, рисуется один раз и подходит ко всем вещам плоскости;
- **эмблемы** — лев, орёл, лилия и т. п.: рисуются один раз, игрок выбирает место (грудь, спина, плечо, шлем);
- маска всегда обрезается по непрозрачным пикселям вещи.

**Связь с баннерами:**
- герб составляется на ванильном баннере (ткацкий станок) и переносится на вещь в мастерской: щит на груди / на всю грудь и спину (как сюрко) / на спину плаща;
- переносится **список слоёв баннера**, а не картинка; для каждого ванильного узора баннера — своя версия под броню (рисует художник), пока её нет — уменьшенный ванильный узор.

**Редактор:** окно мастерской — вращаемая фигурка с предпросмотром, список слоёв (добавить/убрать/переставить), выбор узора, места и материала, стоимость (краска, нить, золото, серебро). Нанести можно только подходящее (на латы — роспись и инкрустацию, на ткань — нашивку). Мастерские — по ремёслам (портной; оружейник/ювелир) — на согласование.

## 12. Этапы

Проверочный набор вещей (художник рисует параллельно):

| Вещь | Что проверяет |
|---|---|
| Акетон с длинными рукавами | обычная мягкая вещь, окраска |
| Короткая кольчуга | частичное перекрытие: акетон виден из-под рукава |
| Сапоги + поножи | стык на голени, порядок слоёв |
| Хундсгугель | плоская часть + выступающее забрало |
| Плащ с капюшоном | накидка, правило со шлемом |

| Этап | Что сделать | Готово, когда |
|---|---|---|
| 1. Слоты | `ArmorSlot`, хранение 12 ячеек, свой экран инвентаря, синхронизация | вещь надевается/снимается, сохраняется после перезахода, другой игрок «знает», что надето |
| 2. Плоская отрисовка | две оболочки, склейка, порядок, кэш, скрытие слоя скина | на персонаже видны акетон, кольчуга, сапоги, поножи — в правильном порядке, без мерцания |
| 3. Описание вещей | билдер `.armor(...)` и др., подсказки (слот), вес | проверочные вещи объявлены в `ModItems`, видны в «Доспехах», вес учитывается |
| 4. Выступающие модели | формат (после решения), загрузка, крепление к костям, шаблон Blockbench | забрало хундсгугеля двигается с головой |
| 5. Окраска и капюшон | окраска при склейке, `_overlay`, правило «капюшон — шлем» | акетон любого цвета; капюшон не надевается на хундсгугель |
| 6. Кастомизация | украшения, баннеры, редактор | узор и герб на накидке, инкрустация на нагруднике |
| 7. Защита | **сначала дизайн**: типы урона (рубящий, колющий, дробящий), вклад слоёв | — |
